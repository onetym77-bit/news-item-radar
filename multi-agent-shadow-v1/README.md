# 다중 에이전트 그림자 실행 v1

이 폴더는 기존 일일 브리핑을 대체하지 않고, 같은 입력자료로 다중 에이전트 결과를 비교하기 위한 시험 영역입니다.

## 1단계: 공동 입력 스냅숏

`freeze_input.py`는 `source-scout-v1/output/daily_feed_latest.json`을 읽어 다음을 포함한 불변 입력 스냅숏을 만듭니다.

- 원자료 전체의 SHA-256 지문
- 수집 시각, GitHub 실행 ID, 코드 SHA
- 후보 레인별 건수
- 기존 시스템과 그림자 시스템이 공유할 전체 피드
- 공식 장부와 브리핑 변경을 금지하는 계약

스냅숏은 GitHub Actions의 별도 artifact로만 보관합니다. 이 단계에서는 모델을 호출하거나 공식 브리핑·기사 장부를 수정하지 않습니다.

## 실행

```bash
python multi-agent-shadow-v1/freeze_input.py \
  --feed source-scout-v1/output/daily_feed_latest.json \
  --output shadow_input_latest.json \
  --run-id 12345 \
  --code-sha abcdef
python multi-agent-shadow-v1/freeze_input.py \
  --output shadow_input_latest.json \
  --verify
```

다음 단계에서는 발굴·편집 평가·반론 에이전트가 이 스냅숏만 읽도록 공통 출력 스키마와 오케스트레이터를 연결합니다.


## 2단계: 에이전트 공통 판정 계약

`schemas/candidate_assessment.schema.json`과 `contracts.py`는 모든 전문 에이전트의 결과를 같은 구조로 제한합니다.

- 원문 인용과 출처 ID 없는 사실 주장을 거부합니다.
- 확인된 사실과 미확인 주장을 분리합니다.
- 경쟁 가설 두 개 이상과 판별 근거를 요구합니다.
- 현재 질문 품질 게이트와 같은 6개 항목·12점 점수를 사용합니다.
- PASS는 8점 이상과 시민 손실·경쟁 가설·반증 기준의 필수 점수를 요구합니다.
- 독립 교차 근거가 없는 후보는 편집 제안 단계로 보낼 수 없습니다.
- 내부 추론문 대신 800자 이하의 공개 가능한 판단 요약만 저장합니다.

다음 단계에서는 이 계약을 사용해 발굴·편집·반론 에이전트의 모의 실행과 총괄 오케스트레이터를 구현합니다.


## 3단계: 모의 오케스트레이터

`orchestrator.py`는 모델을 호출하지 않고 실제 스냅숏에서 역할별 작업표를 만듭니다.

- 공공·의정, 시민·생활, 시장·구조 발굴은 서로 겹치지 않게 병렬 배정합니다.
- 편집 평가와 반론 검증은 발굴 결과 뒤에 순차 배정합니다.
- 당일 검증 후보가 2건보다 적을 때만 보충 탐색을 실행하도록 조건을 기록합니다.
- 총괄 단계가 최종 분류를 소유하되 공식 장부와 브리핑 변경은 금지합니다.
- 작업표 자체도 SHA-256 지문으로 검증하고 별도 artifact로 30일 보관합니다.

역할별 판단 원칙은 `agents/ROLE_CONTRACTS.md`에 있습니다. 다음 단계에서 이 작업표와 공통 출력 계약을 OpenAI 에이전트 실행기에 연결합니다.


## 4단계: 실제 AI 그림자 실행기

`live_runner.py`는 OpenAI Agents SDK를 사용해 선택된 후보를 네 번 심사합니다.

1. 출처 성격에 맞는 발굴 에이전트 또는 보완 탐색 에이전트
2. 앞선 답을 보지 않는 독립 편집 평가 에이전트
3. 앞선 답을 보지 않는 독립 반론 검증 에이전트
4. 세 독립 의견을 압축해서 비교하는 총괄 에이전트

기본 시험은 후보 1건, 최대 4회 모델 호출입니다. 후보는 최대 2건, 호출은 최대 8회로 코드에서 제한합니다. 후보 순위는 단순 수집 점수뿐 아니라 실제로 연결 가능한 검증자료와 문맥 충실도를 함께 반영합니다. 임시 질문 문구는 주제 일치 계산에서 제외하고, 서로 다른 구체 핵심어가 두 개 이상 겹칠 때만 검증자료를 최대 2건 붙입니다. 데이터셋 제목·설명과 스키마 확인 대기 자료는 주제가 비슷해도 근거로 전달하지 않으며, 실제 값 행까지 확인되어 `verification_usable=true`인 자료만 보조 근거가 될 수 있습니다. 검증자료가 없으면 후보 원문만 전달합니다. 보충 풀에서는 오래된 자료와 수치 기준기간 등 문맥 잠금이 미완료된 발언을 유료 심사에서 제외합니다. 동일 원문 재등장 레인도 새 근거 없이 다시 심사하지 않습니다. 문맥이 해결된 새 후보 또는 독립적인 새 값 자료가 발굴 레인에 들어오면 재검증할 수 있습니다. 적격 후보가 없으면 0건·0회 유료 호출로 정상 종료하고 문맥 보류·중복 제외 건수를 남깁니다. 에이전트는 인용문과 원자료 ID만 작성하고, 출처명·URL은 검증된 입력 스냅숏에서 시스템이 연결합니다. 각 단계는 구조화된 공통 출력 계약을 통과해야 하며, 인용문·출처 ID·URL이 실제 입력과 일치하지 않으면 전체 실행을 실패시킵니다.

유료 실행은 `Run paid multi-agent shadow trial` 워크플로를 메인 브랜치에서 수동으로 실행할 때만 가능합니다. `OPENAI_API_KEY` 저장소 비밀값과 확인 문구 `RUN_PAID_SHADOW`가 모두 필요합니다. 예약 실행과 코드 병합은 이 워크플로를 시작하지 않습니다.

결과 JSON은 30일 보관되는 별도 artifact에 저장되고 후보명·최종 판정·근거 수준·역할별 토큰 사용량은 GitHub Actions 실행 요약에도 표시됩니다. 공식 브리핑·질문 장부·검증 장부에는 반영되지 않습니다. Agents SDK의 추적도 꺼서 입력과 판단 결과가 별도 추적 로그로 전송되지 않도록 했습니다.
