# 월·수 통합 헤드 에이전트 v4

목표: 서울시민 대상 6~7분 방송 기획 리포트로 확장 가능한 질문을 매주 월·수 검토한다. **매주 2~3건은 성과 목표이지 할당량이 아니며, 품질 미달이면 0건과 병목을 함께 기록한다.** 인기 있는 사안뿐 아니라 아직 관심이 낮아도 시민이 알아야 할 공익 위험을 별도 경로로 찾는다.

## 한 번의 실행 계약

```text
수집·의미 분석                         그림자 검토 큐
뉴스 본문 ──────────┐                 최근 구의회 L3 ─┐
서울시의회 신규 문맥 ┼─> 입력 계약      시민제안 ────────┼─> 사람 판정 대기
서울시 감사 카드 ────┤                 유튜브 ──────────┘
의회 전량 아카이브 ──┘
        │                                      │
        ├─ 본문 근거·HTTPS 원문·사건 문맥 검사      │ 자동 승격 금지
        ├─ 정확히 같은 사안만 군집                  │
        ├─ 출처별 균형 입력 최대 10건               │
        ├─ 반복 문서·출처와 방송 확장성을 함께 정렬  │
        ├─ 1차 가설·질문 합성                        │
        ├─ 기계 품질 검사                            │
        ├─ 2차 독립 반론 검토                        │
        └─ 운영 후보 0~3건 ────────────────┬─────────┘
                                           ▼
                               통합 상태·보류·판정 대기 화면
```

통합 헤드는 모든 소스를 같은 후보로 취급하지 않는다. 최근 구의회 L3·시민제안·유튜브 그림자 소스는 같은 실행 결과에 포함해 누락 없이 보여주지만, `proposals`에는 넣지 않는다. 반면 전량 아카이브 의미 분석은 원문 앵커와 미검증 경계를 유지한 채 운영 입력으로 넘겨 통합 헤드가 반복성·비교 가능성·현장 취재 가능성을 다시 판정한다.

| 단계 | 하는 일 | 실패 시 |
|---|---|---|
| 입력 계약 | 식별자, 출처, HTTPS 원문, 15자 이상 본문 근거, 제목 외 문맥 확인 | `INPUT_HOLD` |
| 정규화·군집 | 출처군과 정확히 같은 사안명을 함께 만족할 때만 중복 병합 | 별도 발언·사건은 유지 |
| 기획 합성 | 시민의 선택·갈등·형평성을 시험할 가설과 두 질문 작성. 선택된 모든 입력 ID를 정확히 한 번 평가 | 누락·중복·미등록 ID면 한 번 재요청, 다시 불완전하면 실행 실패 |
| 기계 검사 | 연속 인용, 비반복 제목, 구체적 질문, 반대 설명, 첫 취재, 방송 장면 검사 | `HOLD` |
| 독립 반론 검토 | 홍보·주장·정책 제안을 사건으로 오인했는지 재심 | `HOLD` |
| 사람 판정 | 운영 후보와 출처별 그림자 큐를 분리해 판정 | 자동 기사 승인 없음 |

## 두 개의 발굴 경로

| 경로 | 무엇을 찾는가 | 관심도 역할 |
|---|---|---|
| 시민 관심 | 공감·분노·생활비·불편·갈등·반복 경험 | 검색량·기사 확산은 탐색 보조 신호 |
| 공익 감시 | 안전·권리·취약계층·공공재정·행정책임의 문서화된 공백 | 관심이 낮아도 공식 감사·점검·원자료 근거가 있으면 검토 |

공익 감시는 실제 피해가 발생했다고 단정하는 경로가 아니다. 감사·점검·공식 기록에서 위험 통제의 공백, 적용 대상, 책임 주체가 확인될 때 ‘피해가 있었나’보다 ‘필수 보호 절차가 실제로 작동하는가’를 검증한다. 막연한 가능성이나 키워드만 있는 항목은 통과시키지 않는다.

## 출처 경계

- 운영 합성 입력: 뉴스 본문 판정, 서울시의회 신규 발언 문맥, 서울시·25개 자치구의회 전량 아카이브 의미 분석. 아카이브 단서는 원문 발언의 사실성을 확정하지 않으며, 반복 문서·출처 수와 방송 확장 점수는 입력 순서를 정하는 보조값일 뿐 최종 선정 근거가 아니다. 기존 취재 착수·사람 판정 사안은 다시 열지 않는다.
- 그림자 사람 판정: 사람이 `VERIFY`로 지정한 서울시 감사 카드, 최근 자치구의회 L3, 시민제안, 유튜브. 감사의 `START_REPORTING`·기각·보류 및 각 큐의 기존 판정 ID는 다시 노출하지 않는다.
- L2 관측: 응답소 공개 민원사례. 시민 진술과 기관 답변을 분리하며 아직 질문 후보를 만들지 않는다.
- 보조·미연결: 검색 관심도, 공개 커뮤니티·직접 제보, 단체장 SNS, 건설알림이. 연결 부족을 0건 또는 현상 부재로 해석하지 않는다.

## 운영

- 정식 통합 실행: 매주 월·수 09:00 KST 및 수동 실행. 뉴스·서울 원자료·감사·최근 구의회 L3·의회 전량 아카이브·시민제안 수집을 완료한 뒤 통합 헤드와 화면 갱신까지 한 회차로 묶는다. 전량 아카이브 워크플로는 원문이 아닌 파생 상태와 의미 분석 결과만 저장소에 남긴다.
- 모델 호출: 기획 합성 1회가 원칙이다. ID 완전성 위반 시 정확한 누락 사유와 필수 ID 목록으로 1회만 재요청하며, 다시 불완전하면 산출물을 만들지 않고 실패한다. 제안이 있으면 독립 반론 검토 1회가 추가된다. 유튜브 의미 검증은 별도 그림자 호출이다.
- PR: 모델 호출 없이 단위 테스트, 입력 매핑 드라이런, 소스 정책 검증만 수행.
- 실행 결과: `editorial-v4/output/latest.json`과 7일 보관 `integrated-head-audit` artifact.
- 화면: 출처별 입력·모델 선택·운영 후보·그림자 판정 대기 수를 한글 상태로 표시한다. 감사·기타 통합 검증 카드도 별도 영역에 빠짐없이 표시한다.
- 판정: 카드의 `판정 ID 복사`와 `판정 화면 열기`를 이용한다. 운영 후보와 감사·기타 통합 검증 카드는 `Review editorial v4 card`, 구의회·시민제안·유튜브 카드는 각 출처별 판정 워크플로에서 정확한 ID로 처리한다. 완료·기각·보류된 카드는 다음 UI 갱신에서 대기 영역에서 제외된다.

2차 검토 통과도 사실 확인이나 기사 승인이 아니다. 피해·예산 소멸·사업 실패·기존 보도와의 차별성은 취재로 확인한다.

## 품질 회귀 기준

[QUALITY_REGRESSION.md](QUALITY_REGRESSION.md)의 실제 편집 사례를 기준으로 다음을 반복 확인한다.

- 제목·주제·시민 질문·뜻밖의 질문이 같은 문장을 반복하지 않는다.
- 기사 제목, 의원 발언, 홍보 문구만으로 문제 발생을 만들지 않는다.
- 새 사업이나 단일 발언은 데이터가 없다는 이유만으로 버리지 않되, 구체적 갈림길과 검증 경로가 있어야 한다.
- 같은 회의록 URL에 여러 발언이 있어도 URL만으로 합치지 않는다.
- 최신 입력이 0건이어도 신선도 유예·문맥 보류·사람 판정 제외 수를 구분해, 소스 미연결로 잘못 표시하지 않는다.
- 6~7분 리포트의 당사자·현장·대조 자료가 없으면 보류한다.
- 운영 후보 0건과 그림자 판정 대기 N건을 명확히 구분한다.


## 자동 품질 회귀 게이트

- `quality_regression_cases.json`: 실제 편집 오류와 허용 사례를 고정한 기계 판정 표본이다.
- `evaluate_quality_regression.py`: 모델 호출 없이 현재 게이트로 모든 표본의 기대 판정을 재현한다.
- `test_quality_regression.py`: 필수 사례가 삭제되거나 판정이 달라지는 변경을 차단한다.
- PR과 정식 워크플로에서 `python -X utf8 editorial-v4/evaluate_quality_regression.py`를 실행한다.

이 게이트는 모델의 문장 품질 전체를 보증하지 않는다. 다만 이미 확인한 오판을 같은 코드 변경으로 되살리지 못하게 한다.
