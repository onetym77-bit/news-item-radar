# 서울 기획 아이템 에이전트 시스템 v1.6

기존 예약 작업을 하나의 상태 기반 편집 흐름으로 묶는다.

## 실행 흐름

1. 관심 레이더가 08:00, 12:00, 17:30에 원천 신호를 수집한다.
2. 일일 브리핑이 09:30에 오전 신호와 최근 기록을 읽어 후보를 선별한다.
3. 일일 브리핑은 질문 게이트로 검증할 현상을 고르고, 실제 분석 뒤 기사 게이트를 통과한 후보만 `S`, `E`, `P` 세 축으로 평가한다.
4. 편집자는 `EDITOR_FEEDBACK.md`에 채택·보류·탈락 의견을 남긴다.
5. 월요일 감사 작업이 최근 7일의 산출물과 피드백 반영 상태를 점검한다.

## 기준 파일

- `SYSTEM_MANIFEST.md`: 현재 자동화가 사용할 단일 활성 구성
- `AGENT_POLICY.md`: 공통 판정·중복·상태 전이 규칙
- `QUESTION_QUALITY_GATE.md`: 중심 질문·시민 손실·경쟁 가설·판정선 기준
- `ORIGINALITY_AND_TEST_GATE.md`: 출처 프레임 차감·양방향 근거·최소 판정·질문 가족 기준
- `QUESTION_QUALITY_AUDIT.csv`: 활성 대기열의 최신 질문 품질 점수와 재심사 결과
- `SOURCE_FAMILY_REGISTRY.md`: 출처군, 근거 계보, 시민 장면 상태 규칙
- `ITEM_LEDGER.csv`: 후보별 누적 상태 장부
- `EDITOR_FEEDBACK.md`: 사람이 에이전트에 되돌려주는 편집 피드백
- `RUN_METRICS_TEMPLATE.md`: 일일 실행의 작업량·원문·장부 건수 고정 계측 형식

## v1.6 핵심

- 출처군별 할당량 대신 핵심 생활 의제에서 구조 변화를 찾는다.
- 구체적인 문제 징후 또는 분해 가능한 구조 자료라는 근거 앵커가 있어야 질문 품질 평가에 진입한다.
- 사업명·정책 목적·비교 없는 단일 계약액에서 피해를 상상한 질문은 FAIL / N/A로 미채점한다.
- 피해 사례가 없어도 분모·기간·분해축이 있는 실제 총액·거래·이용 자료는 질문을 시작할 수 있다.
- 긴장·반전, 시민 손실, 분포·배제, 경쟁 가설, 책임, 반증·판정선을 12점으로 평가하고 8점 이상과 필수 항목을 요구한다.
- 각 PASS에는 중심 질문 한 개, 경쟁 가설 두 개 이상, 기사 전환·축소·폐기 판정선을 남긴다.
- 질문 게이트를 먼저 통과시키고 실제 분석 뒤 기사 게이트에서 구조성과 시민 영향을 판정한다.
- 공식 발표와 통계도 발표가 답하지 않은 질문을 만들 수 있으면 출발점으로 사용한다.
- 질문 원석은 5~10건, 우선 검증은 2~4건을 목표로 하며 적은 날도 정상이다.
- 출처가 이미 한 해석은 질문 품질 고득점이어도 독창성 게이트에서 막는다.
- 시민 손실 근거와 반대 근거를 모두 찾고 24시간 이내 최소 판정이 가능한 질문만 우선 검증한다.
- 공공 계열 출발이 60%를 넘으면 비공공 경로 보정 탐색을 의무화한다.
- 영향 집단·손실·작동 원리·결정 주체가 겹치는 질문은 한 질문 가족으로 병합한다.

기존 `briefing-v3.0-draft`의 매력도·제작성 기준과 `daily-briefing-v4`의 편집 게이트에 질문 품질·독창성 v1.6를 연결한다. 이 폴더는 두 기준을 예약 실행에서 함께 적용하기 위한 연결 계층이다.

`SYSTEM_MANIFEST.md`에 명시되지 않은 초안과 구버전 실행기는 참고 자료이며 예약 작업에 사용하지 않는다.

## 실행본 보존

- 레이더는 호환용 대표 파일 `YYYY-MM-DD-SLOT.md`와 보존본 `runs/YYYY-MM-DD-HHmm-SLOT.md`를 함께 쓴다.
- 일일 브리핑은 호환용 대표 파일 `YYYY-MM-DD.md`와 보존본 `runs/YYYY-MM-DD-HHmm.md`를 함께 쓴다.
- 대표 파일은 같은 날 재실행하면 최신 결과로 바뀔 수 있지만, `runs`의 보존본은 덮어쓰지 않는다.
- 장부의 `source_report`에는 날짜가 아니라 보존본의 상대 경로를 기록한다.

## 자동화의 쓰기 권한

- 레이더: 자신의 산출물만 작성한다.
- 일일 브리핑: 자신의 산출물, `ITEM_LEDGER.csv`, `QUESTION_QUALITY_AUDIT.csv`, `EDITOR_FEEDBACK.md`의 처리 상태만 수정한다.
- 주간 감사: 자신의 산출물만 작성한다.
- 모든 예약 작업은 `README.md`, `AGENT_POLICY.md`와 기존 편집 기준 파일을 수정하지 않는다.
