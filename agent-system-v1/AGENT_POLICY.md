# 공통 에이전트 운영 규칙

활성 버전: v1.7  
활성 파일은 `SYSTEM_MANIFEST.md`, 출처 독립성은 `SOURCE_FAMILY_REGISTRY.md`를 따른다.

## 목표

서울 시민이 겪는 구조적 비용·위험·권리·접근 격차를 발견하고, 그 문제가 생활 장면과 독립 근거로 확인된 경우에만 편집회의 단계까지 올린다. 관심도나 관측 편의보다 공익성·지속성·책임성을 먼저 판정하며, 매일 정해진 개수를 채우지 않는다.

## 두 단계 게이트

구조적 문제가 이미 입증된 소재만 찾지 않는다. 먼저 해석되지 않은 현상에서 새 질문을 만들고, 그 질문을 검증한 뒤 기사 가치를 판정한다.

### 1차: 질문 품질 게이트

`QUESTION_QUALITY_GATE.md`를 적용한다. 먼저 구체적인 문제 징후 또는 분해 가능한 구조 자료라는 근거 앵커가 있는지 확인한다. 그 뒤 객관적 현상, 시민의 돈·시간·기회·선택권·안전·권리 이해관계, 검증 경로가 모두 있는지 확인한다. 그다음 긴장·반전, 시민 손실·권리, 분포·배제, 경쟁 가설, 책임·변경 가능성, 반증·판정선을 각 0~2점으로 평가한다.

사업명·정책 목적·비교 없는 단일 계약액만 있고 피해자·손실·동선을 상상해 붙인 질문은 점수를 매기지 않고 `FAIL / N/A`로 둔다. 실제 총액·거래·이용·지원 실적처럼 분모와 분해축이 있는 구조 자료는 피해 사례가 없어도 진입할 수 있지만, 분해 결과를 확인하기 전에는 집중·소외를 결론으로 쓰지 않는다.

`PASS`는 12점 중 8점 이상이며 시민 손실·권리, 경쟁 가설, 반증·판정선이 각각 1점 이상이어야 한다. 5~7점 또는 필수 항목이 빠진 질문은 `HOLD`, 0~4점은 `FAIL`이다. “어디에 집중됐나”, “지역별로 다른가”, “실제로 불편한가”만 묻는 템플릿 질문은 HOLD 이하로 둔다.

모든 PASS 원석에는 다음을 기록한다.

1. 기사를 끌고 갈 중심 질문 한 개
2. 구체 집단이 잃을 수 있는 돈·시간·기회·선택권·안전·권리
3. 구조 가설과 자연적·기술적 대안 가설을 포함한 경쟁 가설 두 개 이상
4. 두 가설을 가를 변수와 비교
5. 기사 전환·축소·폐기 판정선

질문 품질 PASS는 우선 검증 진입을 보장하지 않는다. `ORIGINALITY_AND_TEST_GATE.md`에 따라 출처 프레임, 편집적 추가, 같은 중심 질문의 선행보도, 왜 지금 유형을 기록한다. 독창성 PASS와 24시간 이내 최소 판정 실험이 있는 질문만 일일 우선 검증 대상으로 삼는다.

우선 검증 때는 시민 손실을 뒷받침할 가격·거래·민원·상담·분쟁·행동·현장 경로와 구조 가설을 약화할 반대 근거 경로를 각각 한 번 이상 실제 검색한다. 두 번째 경로를 생략한 확인 편향형 검증은 기사 게이트에 진입할 수 없다.

활성 대기열의 최신 질문 품질 판정은 `QUESTION_QUALITY_AUDIT.csv`를 따른다. 기존 `ITEM_LEDGER.csv`의 question_gate 값과 품질 장부가 다르면 품질 장부에 맞춰 단계와 게이트를 갱신하기 전까지 우선 검증 또는 승격 대상으로 사용하지 않는다.

분포·비교·원인 질문은 중심 질문을 검증하는 보조 질문 최대 세 개로 둔다. 이 단계에서는 손실·원인·시민 장면이 아직 입증되지 않아도 되지만 근거 앵커 없이 이를 만들어내서는 안 되며, 무엇을 확인해야 하는지는 구체적이어야 한다.

### 2차: 기사 게이트

질문을 실제로 검증한 뒤 다음을 모두 충족하면 `PASS`다.

1. 의미 있는 집중·격차·불일치·부담·예상 밖의 결과가 확인됐다.
2. 영향을 받는 집단과 규모·지속성·분배를 설명할 수 있다.
3. 원인 가설, 책임 주체, 반증·중단 조건이 있다.

기사 게이트 PASS만 S2 이상으로 승격한다. HOLD는 질문은 유효하지만 결과가 미확인된 상태로 S1 이하에 둔다. FAIL은 분석 결과 특이점이 없거나 기사적 의미가 없는 경우다.

### 행사·티켓·예약 신호

행사성이라는 이유만으로 수집 단계에서 자동 삭제하지는 않는다. 다만 질문이 일정·가격·매진·이용 팁에 머물면 질문 게이트 FAIL이다. 공공자원 배분, 안전, 접근 격차, 독점·환불, 노동, 행사 뒤 지속 영향처럼 분해·비교·책임 질문이 만들어질 때만 검증 원석으로 남긴다.

## 세 축 판정

모든 후보는 서로 다른 의미의 세 등급을 함께 기록한다.

- `S0~S3` 신호 성숙도: 발견된 단서가 편집회의 제안 수준까지 얼마나 검증됐는가
- `E0~E3` 편집 매력도: 예상 밖의 발견, 시민 이해관계, 장면과 질문이 얼마나 강한가
- `P0~P3` 제작 난이도: 실제 방송 리포트 제작에 필요한 시간과 자료·섭외 부담은 얼마인가. 단, 기사 가설이 성립한 `S2` 또는 `S3` 후보에만 부여한다.

등급을 서로 대신 쓰지 않는다. `S0` 또는 `S1`은 제작이 쉬워 보여도 `P 미판정`으로 기록한다. `P0`는 기사 가치가 아니라 검증과 제작에 필요한 시간의 표시다.

## 상태 전이

- `S0 발견`: 단일 원천 신호. 장부에 기록하되 최종 후보로 제시하지 않는다.
- `S1 관찰`: 한 데이터 층 또는 반복 신호가 확인됐다. 다음 확인 조건을 지정한다.
- `S2 검토`: 서로 다른 근거 계보 두 개 이상, `관찰됨` 또는 `당사자 진술` 상태의 시민 행동 신호, 반증 가능한 검증 경로가 교차했다. 일일 브리핑 검토 대상이 된다.
- `S3 제안`: 장소, 검증 자료, 취재 접근법과 실패 대안이 있다. 편집회의 제안이 가능하다.
- `채택`: 편집자가 취재 검토 또는 제작 대상으로 선택했다.
- `보류`: 가치가 있으나 다음 확인 조건이 남았다.
- `탈락`: 중복, 소진, 근거 부족, 서울성 부족 또는 실행 불가 사유가 확정됐다.

등급을 올릴 때는 `ITEM_LEDGER.csv`의 `new_evidence`와 `next_check`를 반드시 갱신한다. 새로운 독립 근거가 없으면 같은 후보를 다시 최종안에 올리지 않는다.

`간접 보도`, `취재 예정`, `없음` 상태의 시민 장면만 있는 후보는 원칙적으로 S1 이하로 둔다. 촬영할 법한 장면을 서술한 것과 실제 행동을 확인한 것을 혼동하지 않는다.

## 일일 브리핑 게이트

최종 제안은 최대 3건이며 0건도 정상이다. 다음 조건을 모두 충족한 `S2` 또는 `S3`만 최종 제안에 넣는다.

1. 서울 시민이 자신의 시간·돈·공간·관계에서 떠올릴 장면이 있다.
2. 질문 게이트와 기사 게이트가 모두 `PASS`다.
3. 정책 발표를 지워도 시민 행동이나 시장 변화가 남는다.
4. 기존 보도와 다른 검증 질문 또는 비교축이 있다.
5. 원문과 독립 출처를 열어 핵심 사실을 확인했다.
6. 공개 데이터, 자체 표본 또는 현장 관찰로 반증할 수 있다.
7. 현장 당사자 섭외 A안과 실패 시 정직한 B안이 있다.

최종안마다 `S/E/P` 등급, 시민 장면, 기존 프레임→새 질문, 새 근거, 검증 경로, 현장 A안, 실패 B안, 중단 조건을 표시한다.\n\n### 세 구역 브리핑\n\n일일 브리핑은 다음 세 구역을 구분한다.\n\n1. **오늘의 편집 제안**: 위 조건을 충족한 S2·S3만 최대 3건 제시한다.\n2. **오늘 4시간 검증할 아이템**: 질문 품질 PASS인 S0·S1 중 review_by 도래, E3, E2 순으로 2~4건을 제시한다. 기사 후보가 아니라 취재·분석 과제임을 명시한다.\n3. **새 질문 원석·후속 관찰**: A·B에 포함되지 않은 PASS/HOLD 현상을 최대 10건 제시한다.\n\n시민 장면이 아직 없는 S1도 두 번째 구역에서 장면 확인 과제로 제시할 수 있다. 계획된 장면을 증거로 세거나 S2로 승격하지 않는다. 기한이 지난 S1은 모두 검증 대기열에 남기고 브리핑에는 당일 집중할 최대 4건과 나머지 기한 초과 목록을 분리해 표시한다.

## 중복과 재등장

최근 브리핑뿐 아니라 `ITEM_LEDGER.csv`의 정규화 주제와 시민 질문을 함께 비교한다. 제목이 달라도 이해관계·장소·핵심 질문이 같으면 같은 후보로 본다.

질문 중복은 `영향 집단 + 시민 손실 + 작동 원리 + 결정 주체`로 비교한다. 네 요소 중 세 개 이상이 같으면 같은 질문 가족으로 묶고 한 회차 우선 검증에는 부모 질문 한 건만 둔다. 새 통계·지역 분해는 보조 가설이나 새 근거로 병합한다.

재등장은 다음 중 하나가 있을 때만 허용한다.

- 새로운 수치 또는 원자료
- 예약·가격·대기·계약 등 시민 행동의 상태 변화
- 기존 가설을 강화하거나 반박하는 독립 채널
- 촬영 가능한 새 현장이나 당사자 접근 경로

재등장 시 무엇이 달라졌는지 한 문장으로 명시한다.

## 장부 후속검증

일일 브리핑은 시간 비율 대신 다음 작업량을 완료한다.

- 최근 24~72시간 자료와 축적 통계에서 질문 품질 게이트 `PASS/HOLD` 현상 원석 5~10건 수집. 점수 평가 전 단순 현상은 원석 수에 넣지 않는다. 0~4건도 탐색 근거가 있으면 정상이다.
- 질문 게이트 PASS 원석 중 우선순위 2~4건을 실제 분해·비교 검증
- `review_by`가 도래했거나 `next_check`를 현재 확인할 수 있는 `S1` 전부 후속검증
- `S0` 재관찰은 회차당 최대 2건

후속검증에서는 장부에 적힌 확인 조건을 실제 검색·원문 확인·교차 검증 과제로 사용한다. 단순히 기존 문구를 다시 읽는 것은 후속검증으로 세지 않는다. 기한이 지난 `S1`은 새 근거가 없으면 `장기 관찰` 또는 `탈락`으로 전환하고 이유를 기록한다.

## 탐색 작업량 계측

일일 브리핑은 신규 탐색, S1 후속검증, S0 재관찰을 구분해 실제 수행량을 기록한다.

- 단계별 검색 질의 수, 원문 시도·성공·실패 수, 검토 후보 수를 기록한다.
- 질문 원석 5~10건, 우선 검증 2~4건, 도래한 S1 전부, S0 최대 2건을 각각 통과·미달·해당 없음으로 판정한다.
- 시간은 전체 실행의 시작·종료 시각만 선택적으로 기록하며 작업 배분의 합격 기준으로 쓰지 않는다.
- 처리 대상 S1이 없으면 `해당 없음`, 모두 처리했으면 `전부 처리`라고 쓴다.

### 두 개의 독립 판정

- `탐색 수행 판정`: 정해진 출처군 탐색, 원석 수집, 원문 확인, 후속검증을 실제로 수행했는지 PASS/DEGRADED/FAIL로 판정한다.
- `편집 산출 판정`: 최종 후보 없음/조건부 후보/최종 제안으로 판정한다.
- 후보 0건은 정상적인 편집 산출일 수 있지만 탐색 작업량 미달을 PASS로 바꾸는 근거가 아니다.
- 핵심 생활 의제 탐색을 수행하지 않았거나 질문 게이트 PASS 원석의 우선 검증을 수행하지 못하면 결손 사유와 함께 최소 DEGRADED다. 질문 원석이 0~4건이라는 사실만으로 DEGRADED 처리하지 않는다. 실행 자체가 불가능하거나 장부·정책을 읽지 못하면 FAIL이다.

### 의제와 출처군 범위

출처군은 탐색 할당량이 아니라 근거의 역할이다. 매 회차는 `SOURCE_FAMILY_REGISTRY.md`의 핵심 생활 의제를 탐색하고, PRICE·BEHAVIOR·VOICE·FIELD·INDUSTRY·PUBLIC·MEDIA·SOCIAL은 발견한 구조 가설을 서로 다른 사실 층에서 검증하는 데 사용한다. 감사·판결·예산·공시·행정통계·민원처럼 구조 변화 자체를 보여주는 PUBLIC 원자료는 발견 출발점으로 사용할 수 있다. 보도자료와 서비스 홍보는 단독 출발점으로 쓰지 않는다.

공공 발표·통계·공공연구 최초 발견이 질문 원석의 60%를 넘거나 우선 검증이 모두 같은 계보면, 우선순위 확정 전에 PRICE·BEHAVIOR·VOICE·FIELD·INDUSTRY 경로에서 보정 탐색을 한 차례 수행한다. 결과가 0건이어도 검색 경로와 제외 이유를 기록한다. 보정 탐색 누락 시 탐색 수행 판정은 DEGRADED 이하로 둔다.

## 원문 확인과 건수 정합성

- 탐색 단서는 넓게 수집하되 질문 게이트 PASS 원석 중 우선순위 2~4건은 원문과 데이터 표를 직접 열어 게시 주체, 시각, 분해 단위, 비교 기준, 핵심 수치와 조건을 확인한다.
- 원문을 열지 않은 신규 원석은 `미검증 원석`으로만 세며 `S0` 장부 등록 대상이 아니다.
- 원문 접근이 실패하면 성공한 것처럼 세지 말고 접근 실패 건수와 URL을 별도로 기록한다.
- 장부 추적은 `S1 후속검증`과 `S0 재관찰`을 분리한다. 두 범주를 합쳐 후속검증이라고 부르지 않는다.
- 추적 결과에는 처리한 `item_id`를 범주별로 나열한다. 건수는 나열된 고유 ID 수와 정확히 일치해야 한다.
- 실행 종료 전 계측 표, 본문 요약, 장부 신규·갱신 행의 건수를 서로 대조한다. 불일치하면 파일 저장 전에 수정하고, 해소하지 못하면 운영 점검에 `건수 불일치`로 기록한다.

## 근거 계보와 시민 장면

- 모든 S1 이상 후보는 장부의 `source_families`와 `scene_status`를 채운다.
- 같은 원자료·보도자료·조사·당사자 발언을 재인용한 문서는 하나의 근거 계보로 센다.
- S2 이상 후보는 브리핑에 근거별 최초 원천, 출처군, 독립 여부를 표로 기록한다.
- `MEDIA` 보도 여러 건만으로 시민 행동 근거가 생기지 않는다. 별도 현장 취재 또는 당사자 진술이 없다면 `scene_status=간접 보도`다.
- 현장 A안과 리드 장면은 제작 계획이다. 확인 전에는 `scene_status=취재 예정`이며 승격 근거가 아니다.

## P 등급과 Sol 승격

- `S0/S1`: `P 미판정`
- `S2/S3`: 제작 경로가 구체화된 뒤 `P0~P3` 부여
- 최종 후보가 없거나 P0가 없다는 이유만으로 Sol 재검토를 요청하지 않는다.
- Sol 재검토는 `S2/E2` 이상 유력 후보에서 원자료 충돌, 복잡한 계산, 법적·평판 위험, 단독성·차별성 판단의 모호함이 실제 승격 또는 보도 여부를 가를 때만 요청한다.

## 파일 변경 권한

예약 실행은 이 문서와 `README.md`, 기존 편집 기준·스킬·프롬프트를 읽기 전용으로 취급한다. 자동으로 수정할 수 있는 상태 파일은 `ITEM_LEDGER.csv`, `QUESTION_QUALITY_AUDIT.csv`, `VERIFICATION_QUEUE.csv`, `EDITOR_FEEDBACK.md`의 처리 상태와 브리핑 최신본·날짜별 이력뿐이다. 레이더와 주간 감사는 상태 파일도 수정하지 않는다. 규칙 개선이 필요하면 산출물에 제안만 남기고 정책을 직접 고치지 않는다.

## 사람의 피드백

실행 전 `EDITOR_FEEDBACK.md`에서 처리되지 않은 항목을 읽는다.

- 채택된 유형은 유사 후보를 무조건 늘리지 말고 채택 이유를 판정 기준에 반영한다.
- 탈락 후보는 사유가 해소되지 않는 한 재추천하지 않는다.
- 영구 제외는 별도 해제 지시가 있기 전까지 적용한다.
- 모호한 피드백을 임의로 확대 해석하지 않는다.

피드백을 반영한 뒤 해당 항목의 `처리 상태`를 `반영`으로 바꾸고 반영 날짜를 적는다.

## 예약 SNS 레이더의 유튜브 원천 신호

이 규칙은 예약된 SNS 레이더 회차에만 적용한다.

1. 작업 폴더에서 먼저 `py .\interest-radar-v2\collect_source_material_v2_1.py`를 실행한다. 예약 회차는 4개 생활 의제를 순환하고 수동 감사에서만 `--audit-all`로 9개 의제를 확인한다.
2. `interest-radar-v2\output\source_material_latest.txt`, 같은 시각의 v2.3 JSON, `youtube_signal_ledger_v2_1.json`, `youtube_query_health_v2_3.json`을 읽어 유튜브 검색 레인·LEAD·반복 확인 군집·발굴 검토함·배경 자료와 네이버 흐름을 발견 단서로 사용한다. 누적 영상 장부 파일명은 예약 호환성을 위해 유지한다.
3. 유튜브 원천을 기록·제외하기 전에는 API JSON의 제목·설명·게시시각을 열고, 공개 영상 페이지에서 썸네일·설명·챕터 중 확인 가능한 항목을 최소 하나 대조한다. 요약 TXT의 제목·주제어만으로 서울 연결 여부를 판정하지 않는다.
4. 서울 연결 판단은 `확인됨`·`미확인`·`불충분`으로 쓴다. 제목·설명·썸네일·챕터에 서울의 구체 장소·상권·생활 현장이 나오면 `확인됨`으로 기록하되, 이것만으로 영상 주장을 사실로 확정하지 않는다. 원문을 열지 못했을 때는 `미확인`이지 `확인 불가` 또는 `무관`이 아니다.
5. 당사자 가능성·상담지원·현장운영자 한 곳에서 손실 표현이 발견되면 `LEAD`로 기록해 원문 확인·후속 검색 대상으로 삼는다. 최근 30일 안에 서로 다른 비언론 채널 두 곳 이상에서 같은 손실 현상이 반복돼야 `CORROBORATED`이며, 두 단계 모두 사실 근거나 기사 후보가 아니다.
6. 생활정보·방법·레시피·혜택 설명과 언론 재유통은 반복 시민 신호 수에서 제외한다. 손실 표현은 있으나 출처 유형이 분명하지 않은 사연·재연 영상은 자동 폐기하지 않고 발굴 검토함에 두어 사람이 판정한다. 쇼츠는 자동 배제하지 않되 독립성·구체성 점수에서 감점하고 단독 근거로 쓰지 않는다.
7. 수집 결과에 YouTube 할당량 제한·키 미설정·네트워크 오류가 있어도 레이더 작업을 중단하지 않는다. 오류와 수집 시각만 운영 점검에 짧게 남기고, 다른 공개 신호를 계속 확인한다.
8. API 키·환경변수 값은 어떤 산출물에도 기록하지 않으며, 예약 실행 중 관찰 채널·검색어·할당량 정책을 임의로 바꾸지 않는다.
9. 댓글은 반복 경험의 표현·지역·섭외 단서를 찾는 용도로만 사용하며 사실·규모·대표성의 근거로 인용하지 않는다.
10. 매 회차는 검색식·API 검색 결과·고유 ID·상세 조회·강제 제외·수집 통과·새 고유 영상·LEAD·CORROBORATED 건수를 기록한다. `검색 결과 0`과 `필터 통과 0`을 같은 실패로 표현하지 않는다.
11. 검색 표현은 행동 변화·비용 증거·생활 장면·당사자 형식 네 레인으로 구분한다. 표현별 수율을 최소 3회 누적한 뒤 통과 0건은 PAUSED, 손실 장면 0건 또는 불일치·소음 50% 초과는 REVIEW로 기록하고 약한 표현을 계속 반복하지 않는다.

## 실패 처리

- 입력 레이더가 없으면 누락 사실과 예상 시각을 운영 점검에 기록하고 다른 출처로 계속한다.
- 원문 접근 실패나 수치 충돌은 숨기지 않고 후보 등급을 내린다.
- 파일 저장 후 다시 읽어 존재, 크기, 제목 날짜를 확인한다.
- 장부 갱신에 실패해도 브리핑 파일을 삭제하거나 덮어쓰지 말고 실행 결과 첫 줄에 알린다.
