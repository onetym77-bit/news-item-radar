# 서울시장·25개 구청장 SNS: 넓고 얇은 L0 연결

현재 범위는 **계정 공식성의 확인**이다. 26개 행정 단위(서울시 + 25개 자치구)를 모두 등록했지만, 26명의 단체장 개인 계정이나 25개 구청 계정을 확인했다는 뜻은 아니다.

## 이번 연결 범위

- 서울시가 직접 공개한 [공식 소셜 미디어 목록](https://mediahub.seoul.go.kr/staticpage/sns.do)에 연결된 서울시 대표 유튜브·인스타그램·블로그 3개를 **기관 계정**으로 등록했다.
- 자치구 25곳의 공식 홈페이지 주소는 [정부24 지자체 누리집 목록](https://www.gov.kr/portal/orgSite?pageIndex=1&srchOrgCd=3200000)의 각 구 항목을 근거로 등록했다. 홈페이지 주소 확인과 SNS 계정 공식성 확인은 별도 단계다. SNS 계정 URL은 구청 공식 홈페이지의 직접 링크를 확인하기 전까지 비워 둔다.
- 서울시장·구청장 **개인 또는 직책 계정**은 기관 계정과 분리한다. 이름 검색 결과나 영상 출연만으로 공식 계정으로 인정하지 않는다.
- 검증기는 SNS 게시물이나 프로필을 접속·수집하지 않고, 공식 목록 페이지가 해당 계정 링크를 여전히 게재하는지만 확인한다.

## 판정 해석

- `CONFIRMED_LISTED`: 공식 목록 페이지에 같은 계정 링크가 확인됨. 계정 내용의 진위나 최근 활동을 뜻하지 않는다.
- `NOT_LISTED_NEEDS_REVIEW`: 목록 페이지는 열렸지만 링크가 보이지 않음. 삭제·비공식 판정이 아니라 재검토 대상이다.
- `SOURCE_UNAVAILABLE`: 공식 목록 접근 실패. 계정이나 게시물이 없다는 뜻이 아니다.
- 미등록: 공식 URL 확인 전 상태. 계정이 실제로 없다는 뜻이 아니다.

## 다음 공통 작업

1. 등록된 26개 공식 홈페이지 첫 화면에서 유튜브·인스타그램·페이스북·블로그 계정 링크 후보만 읽기 전용으로 추출한다. 후보 링크는 계정 승인이나 게시물 수집이 아니다.
2. 구청 공식 홈페이지의 SNS 안내·푸터에서 구청 기관 계정 URL과 이를 가리키는 공식 페이지 URL을 사람 검수 후 함께 등록한다.
3. 구청장 개인 계정은 구청 공식 페이지에서 직접 연결되거나 공적 인증 근거가 있는 경우에만 별도 등록한다.
4. 26개 단위의 공식 링크 확인률과 기술 접속률을 먼저 산출한다. 미등록/접속 실패는 0건 성과로 처리하지 않는다.
5. 공식 유튜브·홈페이지에 한해 L1 목록 20건 이내 표본으로 넘어간다. 게시일·고유주소·원계정 여부만 확인하고, 유망 소스를 선별하기 전 질문 생성은 하지 않는다.
6. 외부 출연 콘텐츠·시민 촬영 영상은 별도 레인으로 두고, 공식 계정 확인과 혼합하지 않는다.

수동·PR 읽기 전용 실행: `.github/workflows/official-social-l0.yml`. 결과는 7일 보관 artifact이며 main 파일, 질문, 브리핑, 장부를 갱신하지 않는다.

홈페이지 후보 추출: `official-social-pilot/scan_official_sites.py`. 접속 실패·첫 화면 후보 0건은 계정 부재가 아니며, 결과는 7일 artifact로만 보관한다.

## 단체장 이름 검색: 홈페이지 링크와 병렬인 L0 후보 경로

공식 홈페이지 첫 화면의 SNS 링크만으로 단체장 개인 계정을 찾지 않는다. 서울시장 및 25개 구청장의 **현재 이름**을 각 지자체 공식 열린시장실·열린구청장실에서 확인한 다음, `이름 + 직책 + 자치구 + 페이스북`으로 검색한다. 검색된 계정은 `name_search_candidates.json`에 **미승인 후보**로만 둔다. 구청 홈페이지의 페이스북 버튼은 기관 계정일 수 있으므로 개인 계정으로 자동 전환하지 않는다.

후보 확정은 본인·기관의 직접 링크나 이에 준하는 독립적인 본인성 근거, 최근 활동 여부를 별도로 확인한 후에만 한다. 검색 노출·동명이인·선거 당시 계정·팬 페이지·제3자 목록만으로는 `accounts.json`의 `officeholder_accounts`에 넣지 않는다. 프로필 접속 실패도 계정 부재로 판정하지 않는다. 이 경로는 계정 발굴용이며 게시물 수집·질문·브리핑·장부로 자동 연결하지 않는다.

## 26명 이름 검색 일괄 시험

`name_search_seeds.json`은 서울시장과 25개 구청장의 **검색용 이름 씨앗**이다. 공식 시장실·구청장실로 이름을 확인한 행과 선거 후 보도를 바탕으로 임시 입력한 행을 구분한다. 후자는 현직자 확인 전까지 공식 명부가 아니다.

`search_officeholder_names.py`는 네이버 웹문서 검색 API로 이름·자치구·직책을 조합해 페이스북 **프로필 주소 후보만** 추출한다. 최대 26명 × 2회 검색, 검색당 첫 5결과, 행정 단위당 최대 3후보로 제한한다. 검색 결과가 기사·기관 계정·동명이인·과거 선거 계정일 수 있으므로 자동 승인하지 않는다. 페이스북 프로필과 게시물을 열지 않으며, 질문·브리핑·장부에도 연결하지 않는다. 검색 오류·키 미설정·검색 후 프로필 주소 미발견은 서로 다른 상태로 남긴다.

PR에서는 키 없이 형태만 시험한다. main의 코드 변경 뒤 한 번 실행하거나 Actions에서 수동 실행할 때만 저장된 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`을 사용한다. 결과는 7일 보관 artifact에만 남는다. 실제로 후보가 발견됐는지는 그 실행 결과를 확인한 다음 판단한다.
