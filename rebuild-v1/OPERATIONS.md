# 재구축 기간 운영표

기준일: 2026-10-12. 기존 예약 정리와 수집 보존에 한정한 전환이다. 최종 추천과 새로운 주간 통합 분석을 완성한 상태는 아니다.

## 유지하는 자동 수집

| 워크플로우 | 시각(KST) | 범위 |
| --- | --- | --- |
| Collect source signals | 매일 08:00, 12:00, 17:30 | 기존 YouTube·검색 원천 수집과 사용량·중복 상태. 모델 해석 없음. |
| Watch 25 district council list windows | 매일 08:45 | 공식 최근목록 변화 관측. 전량 본문 분석과 구분. |
| Collect Seoul raw source feed (rebuild) | 월·수 07:30 | 기존 서울 원자료 수집기를 분리 실행. 장부·판정 큐·브리핑을 수정하지 않음. |

새 서울 원자료 예약은 기존 매일 브리핑 안의 수집을 대체한다. 재구축 기간에는 데이터를 유지하되 새 추천은 생성하지 않는다. 수집 소스의 실제 접근 성공 여부는 각 실행 결과로 확인한다. 실행 시작 시각과 결과 준비 시각은 다르다.

## 제거한 중복·시험 예약

`daily-briefing.yml`, `editorial-brief-v2.yml`, `editorial-v4-fresh-cycle.yml`, `source-onboarding-audit-l4-shadow.yml`, `construction-watch-pilot.yml`, `app-ui-data.yml`의 `schedule`을 제거했다.

일일 브리핑의 push 자동 실행도 차단하고 수동·PR 검증만 유지한다. 정적 화면 갱신·배포는 실제 편집 판정·입력 변경에 따른 경로를 유지한다. 건설·감사 시험 수집은 수동 실행 경로를 보존한다.

## 유료 분석 차단

- 기존 통합 회차 orchestration, 회의록 후보 병합 진단, 유료 멀티에이전트 시험 job은 비활성이다.
- v4 헤드, 구의회 고정/최근 L3, 시민제안 그림자 분석은 PR 무모델 검증만 남긴다. non-PR job은 실행하지 않는다.
- 워크플로우의 OpenAI secret 주입을 제거했다. 저장소의 API 키 자체는 삭제하지 않는다.
- 관심 신호 수집에서 유료 뉴스 본문 해석 단계를 비활성화했다. YouTube 수집 중복도 차단하고 `collect-signals.yml`을 그 상태의 단일 작성 경로로 유지한다.
- 회의록 아카이브는 공식 페이지·의정포털 수집, 캐시, 수집 상태 저장만 수행한다. 분석 호출·분석 산출물 검사와 재게시를 제거했다. 과거 분석 파일은 그대로 보존하고 새 분석으로 표시하지 않는다.
- 이미 시작한 이전 커밋의 실행은 설정 변경으로 취소되지 않는다. 적용 직후 실행 중 작업을 별도로 확인해야 한다.

이 차단은 모델 API 호출 경로에 대한 조치다. GitHub 실행 시간이나 원천 API의 사용량까지 무제한 무료라고 뜻하지 않는다.

## 회복과 재활성화

재활성화에는 원문·질문 품질, 단계별 저장·재시도, 비용 상한 차단을 먼저 검증한다. 과거 워크플로우를 한꺼번에 켜지 않고 새 통합 구조로 교체한다. 수집·해석·편집 판정은 분리한다.

정책 검증: `python -m unittest discover -s rebuild-v1 -p 'test_*.py' -v`.

기존 정책 검증: `python agent-system-v1/validate_discovery_system.py`. 과거 장부 오류는 자동으로 고치지 않고 변경 전후를 비교한다.
