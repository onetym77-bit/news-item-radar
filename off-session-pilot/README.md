# 비회기 3개 소스 소량 시험

실험일: 2026-09-14  
상태: 비활성 진단 도구. 정식 일일 수집기·기사 판정기가 아니다.

## 결과부터 보기

[소량 시험 결과 및 질문 평가](RESULT_2026-09-14.md)

[기존 보완 계획](../district-council-pilot/OFF_SESSION_SOURCE_PLAN.md)에 따라 응답소 통계, 건설알림이 계약·지급 기록, 상상대로서울 시민제안을 시험했다. 기존 로컬 파일·의회 수집·일일 예약·아이템 장부는 변경하지 않는다.

## 무엇을 시험하는가

- **접속 시험 7개 URL:** 통계 1 + 계약 목록 1 + 지급 목록 1 + 제안 목록 1 + 고정 제안 상세 3.
- **편집 표본 7건:** 통계 화면 1 + 계약 3 + 제안 3. URL 수와 우연히 같을 뿐 단위가 다르다.
- 계약·제안은 최초 웹 읽기에 표시된 상위 3건을 고정했다. 직접 요청에서 더 새로운 글이 발견돼도 좋은 결과를 얻기 위해 편집 표본을 교체하지 않았다.
- 지급 목록의 같은 계약 3행은 날짜·중복 집계 오류를 확인하는 보조 표본이며, 새 계약 3건으로 세지 않는다.
- 고정 표본은 최신 아이템 추천 목록이 아니다. 현재 목록의 최신 링크 진단과 별도로 취급한다.

## 실행과 경계

GitHub Actions의 **Probe off-session source access**를 수동 실행할 수 있다. 해당 Python 파일/워크플로의 PR 변경 때에도 실행한다. 예약 실행은 없다.

1. 진단 경계 단위검사.
2. 기존 시스템 검증: `agent-system-v1/validate_discovery_system.py --allow-missing-source-reports`.
3. 공식 HTTPS 주소 7개만 순차 요청. 요청 사이 1초, 요청 제한시간 18초, 응답 크기 3 MB. 이름 해석 실패에만 1회 재시도한다.
4. 같은 호스트의 HTTPS 리디렉션만 허용한다. 403/429이면 해당 호스트의 이후 요청은 중단한다.
5. 로그인·인증키·브라우저 실행·폼 제출·외부 상세 링크 탐색은 하지 않는다.
6. 짧은 진단 결과를 로그와 Actions 산출물로 보관한다. 산출물 보관은 30일이며 원문 HTML은 저장하지 않는다. 로그 보존은 저장소 Actions 설정을 따른다.

제목·짧은 진단 문구의 흔한 이메일/전화번호/세션값은 절단 전에 가린다. 이는 모든 개인 정보의 완전한 익명화를 보장하지 않는다. 운영 확대 전에 본문 저장의 필요성과 비식별화 범위를 다시 검토해야 한다. 개인별 프로필·연락처를 수집하는 용도로 사용하지 않는다.

## 결과 필드의 의미

| 필드 | 의미와 한계 |
|---|---|
| fetched_at, sha256 | 직접 요청 시각(UTC), 응답 지문. 지문 변화는 새 게시물의 증거가 아니다. |
| access, http_status | 전송 상태. HTTP 200만으로 본문·아이템 확보 성공을 판정하지 않는다. |
| first_three_linked_entries | 목록의 최초 고유 링크 최대 3개. 시민제안은 sn 기준으로 중복 제거하고 투표 버튼·빈 번호를 제외한다. 계약은 팝업 호출을 식별할 뿐 계약 상세를 열지 않는다. |
| visible_dates | 페이지에 보인 날짜 후보. 게시일·투표 종료일·지급일·관련글 날짜를 구분한 값이 아니다. |
| stat_values | 화면에서 읽힌 일부 수치. 전체 통계 구조와 기준기간을 완전하게 파싱하지 않는다. |
| diagnostic_excerpts | 접근 여부 확인용 짧은 문구. 전체 원문이나 완성된 근거 기록이 아니다. |
| full_record_parse | 항상 NOT_IMPLEMENTED. 전체 기록 추출을 구현하지 않았다. |
| article_gate | 항상 NOT_EVALUATED. 기사는 자동 통과하지 않는다. |

워크플로 성공은 진단 절차가 실행됐다는 뜻이다. 개별 소스 실패나 보류는 산출물의 상태를 읽어 판단한다. 검색 캐시 실패와 직접 HTTP 실패도 별도로 기록한다.

## 정식 연결 전에 남은 일

1. 검색 결과가 아닌 공식 목록 직접 요청을 최신성 판단의 기본 경로로 사용하고, 수집 시각과 자료 기준일을 분리한다.
2. 시민제안 본문·작성일·처리 상태를 완전한 기록으로 추출하고, 관련 제안을 새 글로 중복 계산하지 않는다.
3. 건설알림이 상세의 계약 식별자·차수·변경 내역을 연결한다. 목록 순번을 영구 번호로 사용하지 않는다.
4. 통계는 전체 합계/처리기관/지역의 범위와 집계 정의를 확인하고, 동일 기간의 비교 가능한 수치를 저장한다.
5. 단순 제안·전언·당사자 경험을 분리한 뒤 기존 질문 품질 및 신규성·최소 검증 게이트를 적용한다.
6. 새 자료가 없는 날에도 보류 질문의 반대 설명과 추가 근거를 확인한다. 자료 부재와 검증 중단을 같은 상태로 만들지 않는다.
7. 지속 관측과 편집자 평가 없이 핵심 소스로 승격하거나 소스별 정밀도를 발표하지 않는다.
