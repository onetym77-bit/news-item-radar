# 감사 결과·시민제안 고정 표본 사람 판정

이 단계는 2026-09-17 [실질 본문 비교 실행](https://github.com/onetym77-bit/news-item-radar/actions/runs/35202083001)의 파생 산출물을 고정 표본으로 사용한다. 감사 공개문 3건, 시민제안 3건이다. 재실행할 때 최신 목록을 다시 읽어 분모를 바꾸지 않는다. 원문 전체나 PDF를 저장하지 않는다.

## 편집자가 할 일

1. 위 실행의 요약에서 각 카드의 짧은 검토 문장과 공식 원문 링크를 확인한다. 감사 문서는 대표 지적뿐 아니라 다른 지적 후보도 살핀다.
2. 판정을 이 대화에서 알려주거나 `source-onboarding-v1/substantive_reviews_2026-09-17.csv`의 `label` 열에 기록한다. 자동 실행은 이 파일을 수정하지 않는다.
3. 판정한 행의 `reviewed_on`에 실제 판정일을 넣는다. `note`는 근거·더 강한 지적·빠진 사례를 300자 이내로 적되 개인 식별정보를 쓰지 않는다.
4. main의 `Review frozen substantive source sample` 수동 실행을 시작한다. 기본 run ID는 35202083001이다. 실행은 같은 artifact를 내려받아 판정만 결합하고 요약을 생성한다.

## 같은 판정 기준

- `PROMISING`: 취재를 시작해볼 만한 구체적 문제와 시민·공공 영향, 확인 가능한 기록·현장이 함께 있다. 최종 기사 확정은 아니다.
- `VERIFY`: 문제 가능성은 있지만 실제 사례, 규모, 책임 주체 또는 현재 상태를 더 확인해야 한다.
- `NOISE`: 해결책 제안·일반 주장에 머물거나 공익적 영향이 약하다.
- `DUPLICATE`: 이미 같은 사안이 평가되어 별도 아이템이 아니다.
- `UNREADABLE`: 본문을 확보하지 못했거나 읽힌 문장만으로 판단할 수 없다.

공식 감사 지적이라는 이유만으로 `PROMISING`으로 보지 않는다. 시민제안도 제안자의 관찰을 사고·피해의 발생 사실로 바꾸지 않는다. 감사의 `document_value`와 `angle_selection`을 기록하는 기존 L4 판정은 이 비교 라벨과 별개다. 기존 L4 값은 자동 변환하지 않는다.

- 감사 문서 한 건에는 여러 지적이 있고 시민제안 한 건에는 보통 제안 하나가 있다. 비율만 직접 비교하지 않는다.
- 다음 성능 평가는 같은 기간의 신규 고유 건수, 실제 읽기 성공, 사람 판정 완료율, `PROMISING`·`VERIFY` 수, 편집 검토 시간과 중복을 함께 봐야 한다.
