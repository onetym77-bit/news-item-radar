# 넓은 신규 소스 시험과 비교 규격

## 목적

신규 소스를 하나씩 완성하기 전에 동일한 얇은 규격으로 시험해 실제 접근성·본문 확보 가능성·편집 수율을 비교한다. 공통 안전장치는 먼저 적용하되, 소스별 전용 해석과 질문 생성은 가치가 확인된 소스에만 투자한다.

## 실행 순서

1. 등록부에 후보 소스와 공식 경로를 기록한다.
2. L0에서 접속 성공·부분 성공·실패를 구분한다.
3. L1에서 소스별 최대 20건의 고유번호·제목·항목 날짜·상세주소만 표본화한다.
4. L2에서 동일 20건 이내의 제한 본문 구조를 확인한다.
5. 사람이 각 표본을 PROMISING, VERIFY, NOISE, DUPLICATE, UNREADABLE 중 하나로 판정한다.
6. 공통 점수표로 기술 상태와 편집 가치를 분리해 비교한다.
7. 낮은 소스는 중단 또는 검증용으로 남기고, 중간 소스는 보조원, 높은 소스만 L3 정교화 대상으로 제안한다.

## 공통 비교 지표

### 기술 지표

- 소스 접근 상태
- 안전하게 확보한 표본 수
- 상세 페이지 접근률
- 본문 확보율
- 게시일 검증률
- 고유 본문 비율
- 상세주소 미해결률

### 편집 지표

- 사람 판정 완료율
- PROMISING과 VERIFY의 합계 비율
- NOISE, DUPLICATE, UNREADABLE 비율

접속 실패 시 표본 수 0을 콘텐츠 부재로 해석하지 않는다. 이 경우 비율 계산을 중단하고 RETRY_ACCESS로 분리한다.

## 판정 기준

편집 가치 판정에는 표본의 80% 이상과 최소 10건의 사람 판정이 필요하다. 전체 표본이 10건 미만이면 전수 판정한다.

- 유효 단서율 35% 이상이고 잡음률 50% 이하: DEEPEN_CANDIDATE
- 유효 단서율 15% 이상: AUXILIARY_CANDIDATE
- 그 미만: STOP_OR_VERIFY_ONLY_CANDIDATE
- 판정량 미달: INSUFFICIENT_REVIEW
- 판정 없음: NOT_EVALUATED

이 결과는 투자 우선순위 제안일 뿐이다. 성숙도 변경, 질문 생성, 브리핑 편입, 장부 기록을 자동 수행하지 않는다.

## 안전 경계

- 표본은 소스별 최대 20건이다.
- L0~L2에서는 질문·시민 피해·기사 후보·품질 점수를 생성하지 않는다.
- 원문 HTML, 본문 전체, 작성자명, 연락처를 저장하지 않는다.
- 기술 실패와 편집 가치 부족을 같은 판정으로 합치지 않는다.
- 한 소스의 실패가 다른 소스의 평가를 중단시키지 않는다.
- L3 이상 전용 해석기는 공통 비교에서 유망성이 확인된 뒤 별도 개발한다.
