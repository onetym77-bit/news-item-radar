# 시민제안 문장 형식 분류 시험

이 시험은 [상상대로 서울 공식 시민제안 목록](https://idea.seoul.go.kr/front/allSuggest/list.do?tab=cateAll)의 첫 고유 제안 최대 25건을 훑고, 그중 이전에 처리하지 않은 최신 항목 최대 5건의 상세만 직접 읽는다. 구의회 비회기 보완 소스의 세 번째 경로를 검토하기 위한 읽기 전용 시험이며, 핵심 발굴 소스나 일일 브리핑에 편입하지 않는다.

## 결과의 의미

- **당사자 경험 진술형:** 제안자가 자신의 신청·방문·이용 등과 불편을 함께 서술한 형식. 실제 발생 여부는 미확인이다.
- **전언·소문형:** 들은 이야기나 소문을 전달한 형식. 공식 발표나 제도 시행의 증거가 아니다.
- **정책 아이디어형:** 설치·도입·개선 등 제안을 중심으로 한 형식. 현행 제도 부재 또는 시민 피해의 증거가 아니다.
- **판별 대기:** 상세 제목 대응이 확인되지 않거나 위 형식에 들어가지 않은 경우.

경험 진술형·전언형에는 분류에 쓰인 짧은 근거 문장을 최대 240자까지 붙인다. 연락처·주민번호 형식·정확한 도로명 번지·동호수·명시된 이름은 가린다. 이 문장은 분류를 설명하는 사람 검토용 앵커이지 사건 발생의 증거가 아니다. 정책 아이디어형은 원문 인용을 저장하지 않는다. 모든 항목에는 첫 확인 경로만 붙인다. 제목·본문 문구에 흔한 표현을 찾는 규칙이므로 복합 진술, 부정문, 인용문, 관련글 혼입을 완벽히 판별하지 못한다. 결과의 분류는 사람이 공식 원문과 대조해야 한다. 공감·비공감·조회 수는 수집하거나 판단에 사용하지 않는다.

## 실행과 보관

GitHub Actions의 **Review citizen proposal experience shadow**를 수동 실행하거나 관련 파일 PR에서 시험한다. 공식 목록 상단 최대 25건을 탐색하되 실행당 상세 본문 처리는 최대 5건으로 제한한다. 처리 한도를 넘은 신규 항목은 이력에 기록하지 않고 다음 실행으로 이월한다. 공식 HTTPS 호스트만 허용하며 응답당 최대 2 MB·20초 제한이다. 이미 정상 처리한 제안 ID는 상세 페이지를 다시 요청하거나 모델에 다시 보내지 않는다. 신규 ID만 분류·검토하고 전체 검증이 성공한 뒤 ID·최초 처리 시각·본문 SHA-256만 main의 처리 이력에 기록한다. 제목·본문·작성자 정보는 이력에 저장하지 않는다.

목록 또는 상세 접근 실패, 모델 실패, 개인정보 경계 검사 실패가 발생하면 처리 이력을 갱신하지 않는다. 따라서 실패를 신규 0건으로 기록하지 않고 다음 실행에서 같은 ID를 다시 시도한다. PR 검사는 처리 이력을 커밋하지 않는다. 검토 산출물은 7일짜리 Actions artifact로만 보관한다.

실행 산출물은 고유 번호·제목·게시일 후보·목록 상태 후보·공식 링크·문장 형식·첫 확인 경로·원본 지문을 담는다. 처리 이력은 산출물과 분리되며 고유 번호·처리 시각·원본 지문만 담는다. 경험·전언형에는 가려진 짧은 분류 근거와 제목에서 찾은 장소 후보·본문의 시간 표현 후보도 담지만 모두 미확인 맥락으로 표시한다. 작성자명, 연락처, 원문 전체, HTML은 저장하지 않는다. 짧은 문장 가림은 완전한 비식별화를 보장하지 않으므로 7일 산출물 밖으로 자동 전파하지 않는다. 제목에 드문 민감정보가 들어갈 가능성은 기본 연락처 가림만으로 완전히 제거할 수 없으므로, 확대 전에 사람 검토 또는 더 엄격한 제목 정책이 필요하다.

HTTP 성공, 상세 제목 대응, 문장 형식 분류, 사실 검증, 기사 판단은 각각 별도 상태다. 첫 관측이나 숫자 증가를 신규 피해·신규 기사로 표현하지 않는다. 공식 목록의 게시일은 화면 근접 텍스트의 후보이며, 상세 기록의 작성일과 대조되기 전까지 완전 검증 날짜가 아니다.

## 시민 신호 검증 전용 화면

그림자 실행에서 당사자 경험 진술이 두 차례 편집 검토를 통과해도 곧바로 공개 화면이나 최종 브리핑에 넣지 않는다. 먼저 실행 artifact의 개인정보 제거 검토 큐 후보를 확인한 뒤 **Publish citizen signal shadow queue** 워크플로에 해당 실행 번호를 입력해 공개 대기열 반영을 승인한다.

공개 카드에는 편집 제목·질문·검증 경로와 최대 240자의 개인정보 제거 근거 문장만 남긴다. 작성자명·연락처·원문 전체·HTML은 포함하지 않는다. 화면의 판정 ID를 **Review citizen signal shadow proposal** 워크플로에 입력해 `PROMISING`·`HOLD`·`DISCARD` 중 하나를 기록한다. 이 판정은 시민 신호 소스의 수율과 품질 피드백이며 기사 승인이나 사실 확인이 아니다.

## 다음 판정 기준

실제 실행 결과에서 상세 제목 대응률, 분류의 사람 확인 정확도, 확인 가능한 시민 경험 진술의 비중을 점검한다. 실행당 본문 표본은 최대 5건이므로 이 단계만으로 소스 수율이나 정밀도를 주장하지 않는다. 일정 기간 동안 신규 탐색 수·당사자 경험형·사람 판정 유망 건수를 누적해 핵심 소스 승격, 보조 소스 유지, 중단 중 하나를 결정한다. 질문 품질·독창성·최소 검증 및 기사 게이트는 기존 시스템과 분리해 유지한다. 기존 질문 장부와 일일 예약은 변경하지 않는다.
