# 의회 지적사항 생명주기 추적기 v1

## 목적

서울시의회와 25개 자치구의회에서 과거에 제기된 행정 문제가 뒤 회의록에서 다시 지적됐는지, 조치·부분 이행·해결 근거가 나타났는지를 찾는다.

이 단계는 기획기사 후보를 자동 확정하지 않는다. 서로 다른 시점의 원문 두 개를 묶어 사람이 검토할 근거 쌍을 만드는 **감시·공익형 보조 경로**다.

## 탐색 범위

- 서울시의회 1곳과 자치구의회 25곳
- 기본 과거 범위: 18개월
- 현재 단서:
  - 서울시의회 원자료 피드
  - 25개 자치구의회 L3 검토 결과
- 과거 단서 보충:
  - 9~18개월 전 회의록에서 반복 지적·미이행·장기 지연 등 구체적인 행정 의무가 있는 발언만 별도 씨앗으로 추출
  - 현재 재지적이 없어도 후속 조치 여부를 다시 검색
- 과거 검색: 국회도서관 지방의정포털 회의록 OpenAPI 본문 검색
- 최신 자료 보완: 기존 서울시의회·자치구의회 공식 홈페이지 수집 경로

지방의정포털이 최신화되지 않은 경우에도 현재 단서는 공식 홈페이지 수집 결과에서 유지된다. 과거 검색 결과가 없다는 이유로 문제가 없거나 해결됐다고 판정하지 않는다.

## 동일 사안 판정

단순 키워드 일치는 동일 사안이 아니다. 다음 축을 함께 비교한다.

1. 책임 기관
2. 영향을 받는 시민
3. 지역·사업·시설
4. 행정이 해야 할 의무
5. 실패·공백의 양상

모델이 같은 사안으로 판정하더라도 비교 문서에 실제 존재하는 연속 인용문이 없으면 결과를 폐기한다.

## 상태

- REPEATED_AFTER_9M: 9개월 이상 뒤 같은 문제가 지속·재발했다고 다시 명시됨
- REPEATED_WITHIN_9M: 9개월 안에 같은 문제가 다시 명시됨
- PARTIAL_ACTION_EVIDENCE: 조치가 있었지만 공백이 남았다는 근거
- RESOLVED_EVIDENCE: 완료·해소 근거
- NO_MATCHING_FOLLOWUP_OR_PRIOR_EVIDENCE: 같은 과거·후속 근거를 찾지 못함

마지막 상태는 **미해결**이 아니다. 회의록의 침묵은 해결·미해결 어느 쪽의 증거도 아니다.

## 실행

GitHub Actions의 **Track recurring council issues**를 수동 실행한다.

필요한 저장소 시크릿:

- CLIK_API_KEY
- OPENAI_API_KEY

기본 실행은 현재 단서 2건과 과거 보충 단서 1건을 포함해 최대 3건, 과거 18개월, 의미 비교 최대 12건이다. 과거 보충 단계는 최대 12개 문서를 읽어 후속 추적 가치가 있는 씨앗을 최대 5건 만든다. API는 검색 목록을 좁히는 데 먼저 쓰고, 비교할 문서만 본문을 읽는다. 키·본문 전문은 산출물에 저장하지 않는다.

산출물:

- issue-lifecycle-v1/output/historical_seeds_latest.json
- issue-lifecycle-v1/output/HISTORICAL_SEEDS.md
- issue-lifecycle-v1/output/latest.json
- issue-lifecycle-v1/output/SUMMARY.md

산출물은 7일짜리 Actions 아티팩트이며 아이템 장부·브리핑·공개 UI를 자동 수정하지 않는다.

## 편집 원칙

- 재지적은 서로 다른 날짜의 원문 두 개가 있어야 한다.
- 미해결·부분 이행·해결은 뒤 문서의 명시적 근거가 있어야 한다.
- 후속 자료를 찾지 못한 상태를 미해결로 표현하지 않는다.
- API 오류·본문 오류는 0건으로 해석하지 않는다.
- 원문 쌍과 다음 확인 자료를 사람이 검토한 뒤에만 통합 헤드 후보로 승격한다.
