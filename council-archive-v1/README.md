# 의회 회의록 전량 아카이브·의미 분석 v1

## 목적

반복 지적, 장기 지연 같은 검색어로 과거 회의록 일부만 찾지 않습니다.
서울시의회와 25개 자치구의회의 회의록 목록을 키워드 없이 순회해 원문을
아카이빙하고, 모든 문맥을 순차적으로 읽어 시민 문제 구조를 찾습니다.

## 1단계: 전량 아카이브

1. 지방의정포털 OpenAPI에서 26개 의회의 회의록 목록을 최신순으로 읽습니다.
2. 최근 36개월 범위가 끝날 때까지 페이지를 이어서 수집합니다.
3. 회의록 원문은 문서 ID와 본문 해시로 중복을 막아 압축 보관합니다.
4. 한 번에 처리할 양을 제한하되, 다음 실행에서 중단 지점부터 계속합니다.
5. 포털 최신일과 각 의회 공식 홈페이지 최신일을 비교합니다.
6. 공식 홈페이지가 더 최신이면 `PORTAL_STALE_USE_OFFICIAL`로 표시합니다.
7. 수집 실패는 0건으로 처리하지 않고 재시도 대기 또는 공식 경로 보완 대상으로 남깁니다.

성동구처럼 공식 홈페이지 인증서 확인이 실패하거나, 성북·동대문처럼 일시적인
연결 실패가 생겨도 지방의정포털 수집 결과를 없애지 않습니다. 대신 공식 최신성
확인이 끝나지 않았다고 분리해서 표시합니다.

## 2단계: 전체 문맥 의미 분석

각 회의록 원문을 약 1만 2천 자 단위로 나누고 모든 조각을 순서대로 분석합니다.
검색어가 포함됐는지가 아니라 다음 구조를 확인합니다.

- 영향을 받는 시민
- 문제를 만드는 제도·사업·행정 결정
- 시민 부담·서비스 공백·안전·권리·공공비용
- 발언이 주장인지, 공식 확인인지, 제안·계획인지
- 아직 확인하지 못한 사실
- 시민이 던질 구체적인 질문
- 통념과 다른 원인·배분·대체수단·부작용 질문
- 6~7분 방송 리포트로 확장할 현장·책임 주체·비교 축

새 사업은 실적 자료가 없다는 이유만으로 제외하지 않습니다. 의미 있는 의원의
질문·발언도 검토 단서로 남기되, 사실 확정과 분리합니다. 행사·인사말·단순 조문
정비·일상적 공사 일정·기관 내부 행정은 후보로 만들지 않습니다.

분석 진행 위치도 캐시에 저장하므로 중간에 멈춰도 다음 실행에서 이어집니다.
의미 분석 결과는 아직 기사 후보가 아니라 사람 검토 전 구조화 단서입니다.

## 저장물

- 전체 원문 아카이브와 재개 상태: GitHub Actions 캐시
- 의미 분석 진행 상태와 누적 단서: GitHub Actions 캐시
- 이번 실행에서 새로 확보한 회의록: 실행 결과물
- 의회별 진척·오류·최신성 판정: `output/status_latest.json`
- 의미 분석 검토 카드: `output/analysis_latest.json`
- 사람이 읽는 진행표: `output/SUMMARY.md`, `output/ANALYSIS_SUMMARY.md`

API 키, 인증정보, 전체 원문은 검토 카드에 노출하지 않습니다.

## 다음 계층

의미 분석 단서를 시간축·유사 사업·다른 자치구별로 묶어 반복 지적, 지역 격차,
미해결 가능성, 해결·부분 조치 근거를 비교합니다. 그 뒤에야 6~7분 방송용 기획
후보 2~3건을 선정합니다.
