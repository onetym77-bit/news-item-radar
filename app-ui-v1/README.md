# 앱 UI v1 — 읽기 전용 운영 화면

## 목표

수집·판정 로직과 분리된 화면에서 다음을 한눈에 확인한다.

- 오늘 실행 상태와 실패·미시도 소스
- 소스별 성숙도(L0~L5)와 최근 결과
- 사람 판정 대기 카드
- 편집자가 선택한 취재 착수 검토 항목
- 최신 브리핑과 근거 링크

## 설계 원칙

1. 화면은 읽기 전용이다. UI에서 질문 품질 장부·아이템 장부·편집 판정을 직접 수정하지 않는다.
2. 접속 실패와 실제 0건을 서로 다른 상태로 표시한다.
3. L0~L2 자료는 아이템 후보로 승격해 보이지 않는다.
4. 각 수치에는 실행 시각과 출처 링크를 함께 표시한다.
5. 로컬 파일 권한 문제를 피하기 위해 초기 데이터는 GitHub Actions artifact 또는 공개된 JSON 엔드포인트에서 읽는다.
6. 데이터가 없을 때 빈 화면 대신 미수집·접속 실패·판정 대기를 표시한다.

## 첫 화면 구성

- 상단: 마지막 실행 시각, 전체 실행 상태, 데이터 신선도
- 왼쪽: 소스 성숙도 필터와 상태 필터
- 중앙: 오늘의 편집 검토 카드
- 오른쪽: 실패·보류·추가 확인 큐
- 하단: 브리핑 원문과 출처 링크

## 단계별 구현

- v1: 정적 HTML/CSS/JavaScript 목업과 읽기 전용 샘플 데이터
- v1.1: GitHub의 최신 JSON/Markdown 산출물 연결
- v1.2: Actions 실행·artifact 상태 표시
- v2: 사람 판정 입력을 별도 승인 화면으로 분리
- 데스크톱 포장: UI 계약이 안정된 뒤 Tauri 또는 Electron으로 전환

이 디렉터리는 수집기·브리핑 생성기·장부를 대체하지 않는다.
