# 앱 UI v1 — 읽기 전용 표시·안전 판정 연결 화면

## 목표

수집·판정 로직과 분리된 화면에서 실행 상태, 소스 성숙도, 사람 판정 대기 카드와 최신 브리핑을 한눈에 확인한다.

## 설계 원칙

1. 화면은 산출물을 직접 수정하지 않는다. 판정은 카드의 정확한 ID를 복사해 GitHub Actions 판정 워크플로에서 기록한다.
2. 접속 실패와 실제 0건을 서로 다른 상태로 표시한다.
3. L0~L2 자료는 아이템 후보로 승격해 보이지 않는다.
4. 각 수치에는 실행 시각과 출처 링크를 함께 표시한다.
5. 데이터가 없을 때는 빈 화면 대신 샘플·미수집·접속 실패 상태를 표시한다.

## 현재 구현

- 정적 HTML/CSS/JavaScript 화면
- `data/latest.json` 형식의 정규화된 데이터 계약
- 실제 데이터 파일이 없거나 읽히지 않으면 샘플 데이터로 자동 전환
- 화면 상단에 `실제 산출물` 또는 `샘플 화면` 상태 표시

`data/latest.json`은 GitHub Actions가 생성하는 읽기 전용 산출물입니다. 뉴스 탐색 신호와 별도로 시의회·응답소 등 일일 피드, 자치구의회 목록 관측, 감사 그림자 평가, 유튜브 검색 시험의 최근 저장 상태를 `sourceExploration`에 정규화합니다. 이 단서는 최종 편집 후보로 자동 승격되지 않습니다. 원자료 수집 실패와 0건을 구분하고, 목록 관측·그림자 평가·본문 판정의 단계를 명시합니다.

이 디렉터리는 수집기·브리핑 생성기·장부를 대체하지 않습니다.

## 구의회 검증 전용 영역

월·수 최근 구의회 L3 그림자 실행에서 발언 문맥·독립 편집 검토를 통과한 가림 처리 카드만 표시한다. 이 영역은 최종 후보가 아니며 공개 브리핑이나 상태 장부로 자동 승격하지 않는다. 편집자는 카드의 판정 ID를 `Review district council shadow proposal` 워크플로에 입력해 `PROMISING`(검토 가치 있음), `HOLD`(보류), `DISCARD`(기각)를 기록한다. 판정 완료 카드는 대기 영역에서 빠지고 이력에 남는다.


## 사람 판정 연결

- 운영 후보와 감사·기타 통합 검증 카드는 `Review editorial v4 card`로 이동한다.
- 구의회·시민제안·유튜브 검증 카드는 각 출처 전용 판정 워크플로로 이동한다.
- 카드마다 판정 ID를 화면에 표시하고 복사 버튼을 제공한다. 제목이나 순번으로 판정하지 않는다.
- 판정 워크플로가 성공하면 `Build app UI data`가 자동으로 다시 실행되어 완료·기각·보류 카드를 대기 영역에서 제거한다.
- 정적 GitHub Pages에 쓰기 토큰이나 API 키를 넣지 않는다.
