# 25개 구의회 회의록 본문 L2 표본

## 목적

25개 구의회 모두에서 최신 회의록 1건씩 실제 본문을 읽을 수 있는지 같은 조건으로 확인한다. 이 단계는 연결·정합성 검사이지 기획 아이템 선별이 아니다.

## 실행

- GitHub Actions의 Sample 25 district council bodies L2 워크플로우를 수동 실행하거나 관련 파일의 PR에서 자동 검사한다.
- 워크플로우는 각 의회의 최신 목록에서 1건을 골라 본문을 요청한다. 25건을 병렬 4개 작업자로 읽고, 기존 수집기의 호스트·요청 수·대기시간 제한을 따른다.
- 결과는 실행 아티팩트의 output/body-l2/sample_latest.json 및 SUMMARY.md에서 확인한다. 실행 시각·회의일·URL·본문 관측 여부·본문 길이·화자 구간 수·목록/본문 메타데이터 대조 결과만 저장한다. 발언 원문은 저장하지 않는다.

## 상태 판정

- BODY_METADATA_MATCH: 본문이 있고 회의일·회의 식별정보가 목록과 일치한다.
- METADATA_UNVERIFIED: 본문은 있으나 회의일 또는 식별정보를 확인할 수 없다.
- METADATA_CONFLICT: 목록과 본문의 회의일 또는 식별정보가 충돌한다.
- PROVISIONAL_BODY: 본문은 있으나 의회의 공개 상태가 잠정적이다.
- BODY_UNAVAILABLE: 목록을 찾았지만 본문을 읽지 못했다.
- UNKNOWN_LIST_WINDOW: 목록에서 적절한 회의록을 확인할 수 없다. 회의가 없다는 뜻이 아니다.
- UNKNOWN_COLLECTION: 접속 또는 파싱 실패. 0건으로 계산하지 않는다.
- FUTURE_MEETING: 회의일이 실행 기준일 이후로 표시된다.

## 승급 경계

이 L2 실행은 질문·브리핑을 생성하지 않고 편집 피드, 검토 카드, 채택·기각 이력에도 쓰지 않는다. source_maturity_registry의 district_councils_25는 그대로 L1이다. 충분한 본문 정합성과 실제 발언 단위 표본을 검토한 뒤 별도 변경으로 L3 후보 추출을 설계한다. 접속 실패·원문 불일치·회의일 불확실성은 침묵하거나 성공으로 환산하지 않고 각 의회별로 보고한다.

## 성공 기준

25개 의회의 결과가 빠짐없이 산출되고, 성공/실패가 혼동되지 않으며, 본문과 목록 메타데이터가 맞는 의회의 범위를 알 수 있어야 한다. BODY_METADATA_MATCH 수가 25가 아니어도 워크플로우 자체는 성공할 수 있다. 미충족 의회는 후속 수집기 보완 대상으로 기록한다.
