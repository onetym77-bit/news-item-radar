# 서울 25개 구의회 수집 연결

기준: 2026-09-14

## 사용 범위

기존 5곳 파일럿은 sources.json을 그대로 사용한다. 25개 연결 구성은 sources_25.json이다. 시의회는 기존 source-scout-v1에서 다루며, 이 목록은 서울 자치구의회 25곳만 포함한다.

GitHub Actions의 **Check all 25 district council connections**를 실행하면 각 공식 목록 첫 2건을 고정해 연결을 점검한다. 25곳×2건은 연결 시험이지 기사 발굴률 시험이 아니다. 서대문은 공식 최근목록의 임시·본회의·상임위·특별위 네 탭 각 첫 5건을 합쳐 문서번호로 중복 제거하고 회의일 내림차순으로 첫 2건을 고른다. 일부 탭 수집이 실패하면 다른 탭으로 대체하지 않고 실패로 기록한다. 목록 정렬이 날짜 내림차순이 아닌 사이트도 있으므로 '목록 앞 2건'을 '가장 최근 날짜 2건'과 같다고 가정하지 않는다.

## 연결 완료의 의미

주소 등록, 목록 읽기, 상세 본문 읽기, 날짜·회차 대조를 따로 확인한다. 단순 홈페이지 접속이나 HTTP 200을 본문 확보로 세지 않는다. 회의록 AI 요약 카드도 발언 원문을 대신하지 않는다.

실행 결과는 output/connections/pilot_latest.json 및 markdown으로 생성되며 실행 산출물에서 30일 보관한다. 연결 상태와 잔여 과제는 CONNECTION_RESULT_2026-09-14.md에 요약한다. 원문 아카이브는 저장소에 커밋하지 않는다.

## 첫 관측·새 자료·실패 구분

- BASELINE: 첫 관측. 새 자료가 없다고 말할 수 없음.
- NEW_IN_VISIBLE_WINDOW: 직전 정상 관측과 비교해 현재 확인한 목록 범위에 처음 보인 문서 주소가 있음.
- NO_NEW_IN_VISIBLE_WINDOW: 확인한 범위의 문서 주소에 새 항목이 없음. 회의가 없었다거나 기사거리가 없다는 뜻은 아님.
- BASELINE_AFTER_FAILURE / BASELINE_WINDOW_CHANGED: 직전 관측이 불완전했거나 표본 크기가 달라 비교 기준을 새로 세움.
- UNKNOWN_COLLECTION / UNKNOWN_LIST_WINDOW: 수집·목록 해석 문제로 신규 여부를 판단할 수 없음.

이전 결과 JSON을 --previous로 전달할 때만 비교한다. 기본 수동 실행은 새 환경에서 시작하므로 BASELINE이다. 회의록 본문 개정은 문서 주소가 바뀌지 않을 수 있어 body_sha256도 보존하지만, 자동 개정 이력 분석은 아직 구현하지 않았다.

## 부담 제한

한 실행 안에서 한 구에 동시에 여러 요청을 보내지 않고 최대 4개 구를 병렬 점검한다. 구별 요청 간격 최소 1초, 10회 상한, 요청 제한 18초를 유지한다. 403·429는 해당 구를 중단한다. 일시적인 주소 해석 실패는 한 번만 재시도하거나 확인된 공식 별칭을 사용한다. 인증서 검증을 해제하거나 접근 제한을 우회하지 않는다.

공유 코드 변경 시 중복 요청을 피하려고 자동 검사는 25개 연결 검사로 통합했다. 기존 5개 파일럿 실행은 수동으로 유지한다.

## 이번에 하지 않은 것

- 회기별 전체 이력 수집이나 모든 첨부자료 수집.
- 일일 예약 편입과 과거 미수집분 자동 따라잡기.
- 자동 질문 품질 승인과 핵심소스 승격.
- 기존 ITEM_LEDGER·편집자 판정·로컬 원본 변경.

따라서 연결 시험이 성공해도 매일 첫 2건만 가져오는 방식을 정식 발굴 운영으로 그대로 채택하면 안 된다. 회기 중에는 여러 문서가 한꺼번에 공개될 수 있으므로 다음 운영 연결 단계에 마지막 관측 문서까지의 페이지 추적과 미검토 문서 대기열이 필요하다.
