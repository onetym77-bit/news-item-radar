# 자치구의회 5곳 수집·질문 탐색 시험
기준일: 2026-09-14 (한국 시간)

## 결론

자치구의회는 서울시 발표자료와 다른 질문을 제공하는 발굴원으로 확대시험할 가치가 있다. 다만 이번 결과만으로 핵심소스 승격이나 자동 브리핑 연결을 승인하지 않는다.

이 시험에서 실제로 확인한 문제는 사이트별 본문 연결 방식, 발언 추출 범위, 회의 식별정보 대조였다. 수집 실패를 아이템 부재로 취급하면 발굴 기회를 놓친다. 그렇다고 이 파일럿에서 발견한 결함이 기존 일일 브리핑의 부진 전체를 설명한다고 단정할 수는 없다.

자동으로 뽑은 검토문단과 원문 대조에서 기획 질문 후보를 만들었다. 의원의 주장, 집행부 설명, 편집자가 추가한 가설을 분리했으며 독립 검증이나 최종 기사 승인은 아직 하지 않았다.

## 표본과 수집 결과

강남·관악·노원·마포·성동의 공식 최신목록 첫 4건을 고정했다. 다섯 구는 사이트 구조와 지역을 달리한 목적표본이지 25개 구의 대표표본이 아니다. 실패 문서를 뒤 순위의 쉬운 자료로 교체하지 않았다.

최종 [실행 결과](https://github.com/onetym77-bit/news-item-radar/actions/runs/34795072772): 본문 **20/20건**, 회의 식별정보 자동 대조 **19/20건**. 자동 검토문단이 나온 문서는 18건이며, 이는 편집 통과 건수가 아니다.

| 자치구 | 본문 확보 | 식별정보 대조 | 관찰 및 잔여 확인 |
|---|---:|---:|---|
| 강남 | 4/4 | 3/4 | 7월 29일 본회의 머리말 날짜 자동 대조 미확인 |
| 관악 | 4/4 | 4/4 | www 주소 DNS 실패 후 같은 공식 사이트의 비-www 주소로 성공 |
| 노원 | 4/4 | 4/4 | 1건에서 자동 검토문단 없음. 원문에 질문이 없다는 뜻은 아님 |
| 마포 | 4/4 | 4/4 | 임시회의록은 확정본 재확인 필요 |
| 성동 | 4/4 | 4/4 | 상세 연결 방식 보완 뒤 본문 확보 |

관악의 원래 주소는 최종 실행에서도 이름 해석에 실패했으나 공식 별칭으로 목록과 4건 본문을 확보했다. 이전 실행에서 관악 자료를 못 읽은 것은 '해당 기간 소스 없음'으로 해석할 수 없다.

각 실행 안에서 최신 4건의 자리를 고정했다. 실행 사이 마포 목록에 새 행이 나타났으므로 처음 실행과 마지막 실행은 동일 문서를 짝지은 성능 비교가 아니다. 이 표는 최종 실행의 20건만 집계한다. 원문 공개 지연 또는 운영 안정성 장기 추정에는 쓰지 않는다.

중간 실행에서 강남 7월 27일 문서의 목록·본문 회차 상충도 관찰했다. 최종 실행에서는 일치했으므로 지속적인 오류라고 단정하지 않되, 재발 시 검토문단을 차단하는 검사를 추가했다.

공개일이 확인되지 않아 회의 후 경과일을 공개 지연으로 해석하지 않는다. 노원·마포의 임시본 표시는 유지하며, 표시가 없는 자료도 확정본이라고 가정하지 않는다.

## 질문 후보: 원문 진술과 편집 가설 분리

### 1. 노원 — 산재 0건은 무사고인가, 집계에서 빠진 사고인가?

- 출처: 9월 7일 본회의 최나영 의원 5분 발언. 고정표본에 포함되며 해당 발언 전체를 원문 대조했다.
- 확인한 것은 발언의 존재다. 의원은 부서 제출자료의 위탁 청소노동자 산재가 최근 5년간 0건인 반면 노동자 면담에서는 부상·자부담 치료 경험을 들었다고 주장했다. 같은 자리의 직접적인 집행부 답변은 확인하지 못했다.
- 원래 발언은 작업방식 개선과 직접고용 요구로 이어진다. 추가할 질문은 고용형태 찬반에 앞서 '0건'의 집계 과정이다.
- 첫 확인 자료: 의원에게 제출된 원자료의 대상·기간·정의, 대행업체 사고보고 항목, 같은 범위의 산재 신청·승인 집계. 실제 연락이나 개인정보 수집은 이번 시험에서 하지 않았다.
- 경쟁 설명: 직영/위탁 구분, 신청/승인 구분, 승인 시차가 다를 수 있다. 범위를 맞춘 뒤 불일치가 사라지거나 부상 주장이 확인되지 않으면 누락 가설을 접는다.
- 판정: 우선 검증 후보. 은폐·미보고가 확인됐다는 의미가 아니다.

### 2. 성동 — 폐원 어린이집의 공공활용 가능성은 무엇이 결정하는가?

- 출처: 8월 27일 행정재무위원회 2차. 고정표본에 포함. 자동 발췌와 인접 답변 일부를 대조했으며 안건 전문·첨부자료·답변 전체 검토는 미완료다.
- 이경미 위원은 매각 결정 이후 공공활용 검토로 방향을 바꾸는 과정에 의문을 제기했다. 김환균 재무과장은 해당 매각 대상 중 한 어린이집의 구조적 안전 문제를 설명했다.
- 의원의 '부실검토' 의혹을 그대로 기사 결론으로 옮기지 않는다. 추가 질문은 돌봄 수요, 보조금 반환 조건, 안전 보강비, 다른 공공 용도를 같은 기준으로 비교했는가이다.
- 첫 확인 자료: 대상 두 시설을 구분한 매각 의결·철회 사유, 안전진단, 용도별 비용과 제약, 지역 수요 자료. 한 시설의 안전 문제를 두 시설 전체에 일반화하지 않는다.
- 경쟁 설명: 새 안전진단, 수요나 제도 조건의 변화가 판단 전환을 설명할 수 있다. 당시 조건과 대안 비교가 충실했다면 '검토 공백' 가설은 접고 변화 원인을 설명한다.
- 판정: 전문·첨부자료를 더 읽은 뒤 검증 착수 여부를 정할 후보.

### 3. 마포 — 급식 거점이 있어도 비·눈 오는 날 언덕 위 어르신의 식사는 이어지는가?

- 출처: 9월 2일 공덕동 행정사무감사. 최신 4건에는 포함되지 않은 보완 탐색 사례다. 고정표본 성과에 합산하지 않는다.
- 김진천 의원의 접근·제설 질의와 김종임 동장의 답변을 대조했다. 비가 많이 올 때 어르신 방문이 줄어든다는 취지의 답변은 있지만, 실제 결식 여부는 확인되지 않았다.
- 제설·낙상 문제에서 한 단계 더 나아가 급식의 '이용 가능성'과 '식사 연속성'을 구분해 묻는다.
- 첫 확인 자료: 날씨별 급식 출석, 거주지 경사와 이동 경로, 대체 식사·배달 지원, 미방문자의 실제 식사 해결 방식. 개인 식별정보 없이 집계부터 확인한다.
- 경쟁 설명: 가족·경로당·배달 등 대체 수단이 작동하면 방문 감소가 결식은 아니다. 대체 지원이 충분하면 결식 공백 가설을 접는다.
- 판정: 별도 검증 후보. 현장 확인 전 취약계층의 피해를 단정하지 않는다.

## 이번에 반영한 수정

- 성동의 별도 회의록 식별번호를 해석해 상세 본문에 연결한다.
- HTTP 성공, 실제 발언 본문, 회의 날짜·회차 일치를 각각 기록한다. 충돌 자료는 자동 검토문단을 내보내지 않는다.
- 긴 발언의 앞부분만 잘라 문제 제기를 잃지 않도록 실제 신호 주변을 발췌한다.
- 출석자 명단·의원 소개가 발언으로 섞이지 않도록 구분한다. 일부 회의 진행 문구도 제외한다.
- 날짜 추출 실패가 발생해도 최신 표본 자리를 유지한다. '임시회'를 '임시본'으로 오인하지 않는다.
- 관악은 공식 호스트의 DNS 실패에 한해 확인한 공식 별칭을 한 번 시도한다. 차단 우회나 인증서 검사 해제는 하지 않는다.
- 요청 간격과 상한, 403·429 중단을 적용한다. 매일 자동 실행하거나 기존 수집기를 바꾸지 않는다.

## 검증과 한계

- 코드 커밋: `a3ce23af6d853caccbf95ad7437e335fdd3461c7`.
- 회귀검사 15개 통과. 긴 발언의 문제 표현 보존, 출석자 명단 제외, 날짜 누락 표본 유지, 회차 충돌 등을 검사했다.
- 기존 발굴 시스템 검사: 오류 0, 경고 12. 온라인 저장소에 없는 과거 source_report 존재 검사만 기존 허용 옵션으로 생략했다. 이전 검토기한 경과 등 기존 경고는 이번 시험에서 임의 변경하지 않았다.
- [GitHub Actions 최종 실행](https://github.com/onetym77-bit/news-item-radar/actions/runs/34795072772) 성공. 이는 진단 프로그램 실행 성공이며 핵심소스 승인이나 질문 품질 합격 표시가 아니다.
- 별도 읽기 전용 코드 검토에서 기존 지적의 반영 여부를 점검했다.

이 결과는 20건 전체를 정독하고 모든 정답 질문을 미리 정한 평가가 아니다. 따라서 질문 통과율, 정밀도, 재현율은 산출하지 않는다. 자동 검토문단 수 역시 아이템 수가 아니다. 무작위 대표표본 또는 안정성 반복시험이라고 주장하지 않는다. 수정 중 취소된 실행은 성공·실패 반복시험으로 세지 않는다.

남은 과제는 관악 공식 별칭 연결의 후속 안정성 확인, 메타데이터 미확인 자료의 대조, 같은 회기 내 중복 제거, 절차 발언의 추가 선별이다. 숫자나 문제 표현이 없는 현상도 질문의 출발점이 될 수 있으므로 키워드 기반 문단 추출을 아이템 탈락 기준으로 사용해서는 안 된다.

다음 검증 우선순위는 노원 원자료 대조다. 수집 범위를 한꺼번에 늘리기 전에 '의회 발언 → 편집 추가 질문 → 첫 자료 확인 → 유지/기각' 한 사이클의 품질을 확인한다.
