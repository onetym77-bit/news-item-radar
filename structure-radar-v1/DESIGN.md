# 서울 기획기사 구조 레이더 v1 — 설계 명세

## 목적

정책 발표·보도자료·단일 바이럴에서 출발하지 않는다. 서울 안에서 반복적으로 관측되는 **수치·공간·이용 행태의 변화**를 먼저 포착하고, 그 변화가 시민의 경험 및 공공데이터 검증 질문으로 이어질 때만 기획기사 후보로 올린다.

이 레이더의 산출물은 기사가 아니라 `관측 신호`다. 신호가 없으면 “이번 실행 후보 없음”을 출력한다.

## 전체 흐름

```text
공개 구조 데이터의 새 값
  → 계절·요일·직전 기간 기준선과 비교
  → 지역·업종·시간대의 이상 변화 탐지
  → 독립 데이터 또는 관심 레이더와 교차 확인
  → 취재 질문·검증 데이터·현장 관찰점으로 변환
  → 편집 검토 후보
```

SNS·유튜브는 구조 변화의 원인이거나 증거가 아니다. 시민이 그 변화를 어떻게 말하는지 확인하는 **관심 레이더** 역할만 한다.

## 1차 데이터 원천

| 축 | 1차 원천 | 관측 단위 | 탐지할 변화 | 기사로 만들지 않는 것 |
| --- | --- | --- | --- | --- |
| 상권 재편 | 서울시 상권분석서비스: 점포·추정매출·상권변화 | 업종 × 상권/행정동/자치구 × 분기 | 개·폐업률, 점포 수, 매출, 프랜차이즈 비중의 지역 편차 | 새 지원사업, 상권 행사, 단일 점포 폐업 |
| 도시 체류·이동 | 서울 생활인구: 내국인·장기/단기 외국인 | 250m/행정동 × 시간·일 | 시간대별 체류 변화, 주중·주말 역전, 특정 생활권의 지속적 이탈·집중 | 축제·사고 당일의 일회성 혼잡 |
| 이동 접근성 | 버스·지하철 승하차 공개 데이터 | 정류장/역 × 시간대·일 | 특정 시간대 이용 변화와 생활권 간 격차 | 노선 개통·운행 공지 자체 |
| 생활 기반 | 공영주차·공공시설 등 이용·점유 데이터 | 시설 × 시간·일 | 공급과 실제 이용의 불일치, 지역별 접근 격차 | 시설 신설 보도자료 |

처음 구현은 **상권 재편 + 생활인구**만 한다. 시간·공간·시장이라는 서로 다른 두 축에서 확인돼야 불필요한 정책 편향을 피할 수 있다.

## 관측 규칙

신호는 아래 조건을 모두 확인해야 한다.

1. **비교 기준이 있다.** 전주가 아니라 같은 요일·같은 시간대, 전분기 또는 전년 동기와 비교한다.
2. **변화가 충분하다.** 우선 절대 15% 이상 변화 또는 전체 지역·업종 중 상·하위 5% 수준을 관찰 후보로 둔다. 숫자가 작은 분모는 제외한다.
3. **공간 또는 집단의 차이가 있다.** 단일 장소가 아니라 최소 세 지역, 또는 하나의 생활권에서 서로 다른 데이터가 같은 방향을 보일 때 우선한다.
4. **일회성이 아니다.** 일 단위 데이터는 같은 패턴이 두 번 이상 반복되거나, 분기 데이터는 다른 독립 지표가 뒷받침할 때만 승격한다.
5. **정책발 신호가 아니다.** 법·지원·공고·사업 시행이 직접 원인인 변화는 후보에서 제외한다. 단, 제도 밖 시장·시민 행동이 독립적으로 확인되면 별도 검토한다.

## 신호 등급

| 등급 | 의미 | 브리핑 처리 |
| --- | --- | --- |
| S0 | 데이터 오류·계절성·단일 이벤트 가능성 | 기록만 하고 보고하지 않음 |
| S1 | 한 데이터에서 관찰된 변화 | 구조 레이더 관찰 목록 |
| S2 | 시간·공간 기준선 통과, 독립 데이터 또는 관심 신호 1개 확인 | 데일리 브리핑의 보류 후보 |
| S3 | 시민 생활 장면, 데이터 검증 질문, 현장 관찰 지점이 모두 명확 | 편집 검토 후보 |

S3여도 인터뷰이 섭외 가능성을 기사 가치와 혼동하지 않는다. 브리핑에는 반드시 A안(현장 섭외)과 B안(현장 관찰·데이터·대체 접점)을 함께 적는다.

## 출력 형식

매 실행은 기존 파일을 수정하지 않고 새 텍스트·JSON 스냅샷을 만든다.

```text
관측 시각 / 데이터 기준일 / 데이터 지연일
신호 등급 / 변화 수치 / 비교 기준
변화가 나타난 지역·업종·시간대
반증 가능성 및 배제한 설명
시민 생활 장면 가설 (확정 표현 금지)
관심 레이더 교차 결과 (있음/없음)
검증 가능한 공공데이터 경로
현장 취재 A안 / 섭외 실패 B안
```

## 운영 주기

| 작업 | 주기 | 역할 |
| --- | --- | --- |
| 생활인구·이동 데이터 수집 | 매일 1회 | 최근 이용·체류 패턴의 관찰 |
| 상권 데이터 수집 | 데이터 갱신일 확인 후 주 1회 | 분기 단위 구조 변화의 후보 풀 갱신 |
| 구조 신호 판정 | 매일 오전 브리핑 전 | 새 수치와 누적 스냅샷 비교 |
| 편집 감사 | 주 1회 | 정책발·단일 이벤트·반복 아이템 제거 |

당일 3회 실행하는 SNS 레이더와 달리 구조 레이더는 데이터 갱신 주기에 맞춰 하루 1회만 실행한다. 오래된 분기 데이터를 “오늘 발생한 변화”처럼 표현하지 않는다.

## 구현 전 준비

1. 서울 열린데이터광장 계정에서 일반 OpenAPI 인증키를 발급한다.
2. 키는 `SEOUL_OPEN_API_KEY`라는 비공개 환경변수에만 저장한다.
3. API 키를 코드·JSON·브리핑·채팅에 넣지 않는다.
4. 첫 실행은 과거 값 수집과 기준선 구축만 한다. 최소 4주(일 단위), 또는 상권 데이터의 최근 4개 분기를 모으기 전에는 자동 S3 승격을 하지 않는다.

## 금지 규칙

- 서울시 보도자료, 자치구 공고, 법·제도 변경을 발견 시작점으로 사용하지 않는다.
- 생활인구의 일시적 급증만으로 “상권 활성화”를 추정하지 않는다.
- 상권 매출 변화만으로 “시민 소비가 늘었다/줄었다”고 단정하지 않는다.
- 공개 집계 데이터를 개인 식별·추적 목적으로 사용하지 않는다.
